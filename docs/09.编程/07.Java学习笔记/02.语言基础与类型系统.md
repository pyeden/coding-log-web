# 02 语言基础与类型系统

## 本章目标

掌握 Java 的两套类型世界（基本类型与引用类型）、类型转换规则、字符串语义，以及 `var`、文本块、`switch` 表达式这些现代语法的边界。目标是写出「不会因为精度、溢出、装箱踩坑」的代码。

## 核心概念

Java 是**静态强类型**语言：变量声明即确定类型，编译期完成类型检查。类型分两类：8 种**基本类型**（primitive）`boolean`、`byte`、`short`、`int`、`long`、`char`、`float`、`double`，以及**引用类型**（reference type），即类、接口、数组、枚举、record。

基本类型没有 `null`，直接存值；引用类型存的是对象引用，默认值 `null`。这带来最经典的差异：基本类型比较用 `==` 比的是值，引用类型用 `==` 比的是引用地址，比较内容必须用 `equals`。

整数有明确位宽与范围：`int` 32 位（约 ±21 亿），`long` 64 位。超出范围会**静默回绕**（wrap-around），不抛异常，这是安全事故的常见源头。需要精确计算时用 `Math.addExact` 等方法显式捕获溢出。

浮点数遵循 IEEE 754，`0.1 + 0.2 != 0.3` 是二进制表示的必然结果。金额计算应使用 `BigDecimal` 并以字符串构造，或全程用最小货币单位（分）的 `long`。`char` 是 16 位 UTF-16 码元，一个**码点**（code point）可能由两个 `char` 组成，所以按字符遍历要用 `codePointAt` 而不是下标。

**装箱**（boxing）让基本类型与包装类相互转换，`Integer` 缓存 -128~127，于是 `Integer a = 127, b = 127; a == b` 为 `true`，而 128 为 `false`。结论只有一条：包装类比较永远用 `equals`。

`var`（Java 10）是局部变量类型推断，编译期推导出确定类型，不是动态类型；它不能用于字段、方法参数，也不能声明为 `null`。文本块（Text Block，Java 15）用三引号表示多行字符串，自动去掉公共缩进。

`switch` 表达式（Java 14 正式）可用 `->` 分支并返回值，无需 `break`，且编译器检查穷尽性（exhaustiveness）。Java 21 起 `switch` 支持**模式匹配**（Pattern Matching for switch，JEP 441），可直接对类型分支。

运算符优先级不值得背，用括号表达意图更可靠。需要留意 `+` 的字符串拼接：只要一侧是 `String`，另一侧就会被转成字符串，因此 `1 + 2 + "3"` 得到 `33`，而 `"1" + 2 + 3` 得到 `123`。

字面量支持下划线分隔（`1_000_000`）与进制前缀（`0x`、`0b`、`0o`），`long` 加 `L` 后缀，`float` 加 `f` 后缀。这些细节在解析配置、协议字段时经常用到，写错一个后缀就可能悄悄变成另一种类型。

作用域上，块级变量离开 `{}` 即不可见，`for` 的循环变量属于循环体。把声明尽量靠近使用点，能显著降低「这个值什么时候被改过」的排查成本。`final` 除了表达不可变，也让 lambda 捕获与编译期常量折叠更明确。

## 代码示例

整数溢出不会报错，必须主动防御：

```java
public class Overflow {
    public static void main(String[] args) {
        int max = Integer.MAX_VALUE;
        System.out.println(max + 1);                 // -2147483648，静默回绕
        try {
            System.out.println(Math.addExact(max, 1));
        } catch (ArithmeticException e) {
            System.out.println("溢出被捕获: " + e.getMessage());
        }
        long wide = max + 1L;                        // 提升为 long 后再运算
        System.out.println(wide);
    }
}
```

`var`、文本块与字符串不可变性放在一起看：

```java
public class ModernSyntax {
    public static void main(String[] args) {
        var name = "Java";                      // 推导为 String
        var count = 21;                         // 推导为 int
        String report = """
                language = %s
                version  = %d
                """.formatted(name, count);
        System.out.print(report);

        String a = "abc";
        String b = a.toUpperCase();             // 返回新对象，a 不变
        System.out.println(a + " / " + b);
    }
}
```

`switch` 表达式与 Java 21 的模式匹配：

```java
public class SwitchDemo {
    sealed interface Shape permits Circle, Square {}
    record Circle(double radius) implements Shape {}
    record Square(double side) implements Shape {}

    static double area(Shape shape) {
        return switch (shape) {
            case Circle c -> Math.PI * c.radius() * c.radius();
            case Square s -> s.side() * s.side();
        };
    }

    static String describe(Object o) {
        return switch (o) {
            case null -> "null";
            case Integer i when i > 100 -> "大整数 " + i;   // when 守卫
            case Integer i -> "整数 " + i;
            case String s -> "字符串长度 " + s.length();
            default -> "其他类型";
        };
    }

    public static void main(String[] args) {
        System.out.println(area(new Circle(1)));
        System.out.println(describe(200));
        System.out.println(describe("java"));
    }
}
```

因为 `Shape` 是 `sealed`，`area` 的 `switch` 无需 `default` 即被视为穷尽，新增子类型时编译器会强制你补分支。

## 常见坑

- **用 `==` 比较字符串或包装类**：字符串常量池偶尔让结果「看起来对」，一旦来自 `new` 或运行时拼接就翻车。
- **`float` 表示金额**：精度丢失不可修复，只能用 `BigDecimal` 或整数分。
- **`int` 乘法溢出**：两个 `int` 相乘即使赋给 `long` 也已溢出，需先 `(long) a * b`。
- **`var` 当动态类型用**：`var x = 1; x = "s";` 直接编译失败。
- **文本块缩进不一致**：结束分隔符的位置决定去掉多少公共空白，拼接 `+` 时容易多出空格。
- **`switch` 忘了穷尽**：表达式形式的 `switch` 必须覆盖所有分支，语句形式才允许无 `default`。
