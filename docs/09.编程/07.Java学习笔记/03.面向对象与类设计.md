# 03 面向对象与类设计

## 本章目标

把类、接口、继承、多态这四件事用对，并掌握 Java 17/21 带来的三种「减少样板代码」的工具：`record`、`sealed`、模式匹配。目标是能判断什么时候用继承、什么时候用组合。

## 核心概念

**封装**（encapsulation）指字段私有、行为公开。字段加 `private` 不是为了「好看」，而是为了保留将来修改内部表示的自由；一旦公开字段，调用方就会依赖它，重构成本直线上升。

**继承**（inheritance）表达 is-a 关系，Java 只支持单继承；**接口**（interface）表达能力契约，一个类可实现多个接口。接口方法默认 `public abstract`，Java 8 起可有 `default` 与 `static` 方法，Java 9 起可有 `private` 方法。实践中优先**组合**（composition）而不是继承，因为继承会把父类实现细节泄漏给子类，形成「脆弱基类」问题。

**多态**（polymorphism）指同一调用在运行时绑定到实际类型的方法实现。判断依据是对象真实类型而非变量声明类型，这就是**动态分派**（dynamic dispatch）。`@Override` 注解应始终写上，让编译器帮你检查签名是否真的覆写了父类方法。

`Object` 是所有类的根，`equals`/`hashCode`/`toString` 三个方法最常被覆写。契约是：`equals` 相等则 `hashCode` 必须相等；反之不要求。破坏这条契约会让对象在 `HashMap`、`HashSet` 中「放进去就找不到」。

`record`（Java 16 正式）用于不可变数据载体：编译器自动生成构造器、访问器、`equals`、`hashCode`、`toString`。它适合 DTO、值对象、多返回值，不适合需要可变状态或继承的场景（record 隐式 `final`）。

`sealed`（Java 17 正式）限制谁能继承：`sealed interface Shape permits Circle, Square` 把类型层次封闭起来，配合 `switch` 模式匹配可实现穷尽检查，这正是 Java 表达**代数数据类型**（Algebraic Data Type）的方式。子类型必须声明为 `final`、`sealed` 或 `non-sealed`。

`instanceof` 模式匹配（Java 16 正式）把「判断 + 强转」合并成一步，减少冗余变量。

接口的 `default` 方法带来一个类似 C++ 的问题：菱形继承。若两个接口提供同名同签名的 `default` 方法，实现类必须显式覆写并用 `Interface.super.method()` 指定来源，否则编译失败。这不是缺陷，而是强制你明确语义。

可见性有四级：`private`（本类）、包私有（无修饰符、同包可见）、`protected`（同包加子类）、`public`。最容易被忽略的是包私有，它其实是模块内封装的基本单位，配合 `sealed` 与模块系统能形成完整边界。

判断该用继承还是组合，可以问三个问题：子类是否真的「是一种」父类？父类实现细节变化时子类能否不受影响？是否需要多态替换？三个答案都是「是」才用继承，否则用组合加接口。

## 代码示例

封装 + 不变量校验，构造函数是守住不变量的唯一入口：

```java
public class Account {
    private final String id;
    private long balanceCents;              // 以「分」为单位，避免浮点

    public Account(String id, long initialCents) {
        if (id == null || id.isBlank()) {
            throw new IllegalArgumentException("id 不能为空");
        }
        if (initialCents < 0) {
            throw new IllegalArgumentException("初始余额不能为负");
        }
        this.id = id;
        this.balanceCents = initialCents;
    }

    public void deposit(long cents) {
        if (cents <= 0) {
            throw new IllegalArgumentException("存入金额必须为正");
        }
        balanceCents += cents;
    }

    public long balanceCents() {
        return balanceCents;
    }

    @Override
    public String toString() {
        return "Account[" + id + ", " + balanceCents + " 分]";
    }

    public static void main(String[] args) {
        Account account = new Account("A-1", 1000);
        account.deposit(500);
        System.out.println(account);
    }
}
```

`record` + `sealed` 构建封闭类型层次，`switch` 分支无需 `default`：

```java
public sealed interface Payment permits CardPayment, CashPayment {
    long amountCents();
}

record CardPayment(String last4, long amountCents) implements Payment {
    public CardPayment {
        if (last4 == null || last4.length() != 4) {
            throw new IllegalArgumentException("卡号后四位不合法");
        }
    }
}

record CashPayment(long amountCents) implements Payment {}

class PaymentPrinter {
    static String describe(Payment payment) {
        return switch (payment) {
            case CardPayment card -> "刷卡 ****" + card.last4() + " 金额 " + card.amountCents();
            case CashPayment cash -> "现金 " + cash.amountCents();
        };
    }

    public static void main(String[] args) {
        Payment p = new CardPayment("1234", 9900);
        System.out.println(describe(p));
        System.out.println(p.equals(new CardPayment("1234", 9900)));  // record 自带值相等
    }
}
```

注意 `record` 的**紧凑构造器**（compact constructor）不需要写参数列表，校验后字段自动赋值。

`equals`/`hashCode` 必须成对覆写，且都用同一组字段：

```java
import java.util.Objects;

public class UserKey {
    private final String tenant;
    private final long userId;

    public UserKey(String tenant, long userId) {
        this.tenant = tenant;
        this.userId = userId;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) {
            return true;
        }
        if (!(o instanceof UserKey other)) {   // instanceof 模式匹配（Java 16）
            return false;
        }
        return userId == other.userId && Objects.equals(tenant, other.tenant);
    }

    @Override
    public int hashCode() {
        return Objects.hash(tenant, userId);
    }
}
```

## 常见坑

- **公开可变字段**：一旦发布就难以收回，优先 `private` + 受控方法。
- **覆写 `equals` 不覆写 `hashCode`**：对象进 `HashSet` 后 `contains` 返回 `false`。
- **在构造器里调用可覆写方法**：子类字段尚未初始化，会读到默认值。
- **`record` 里放可变字段**：`List` 字段虽有访问器，内容仍可变，需要 `List.copyOf` 防御性拷贝。
- **`sealed` 子类漏写修饰符**：必须显式 `final`/`sealed`/`non-sealed`，否则编译失败。
- **用继承复用代码**：优先组合，继承只用于真正的 is-a 且父类为继承设计过。
