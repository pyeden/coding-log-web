# 07 并发编程

## 本章目标

理解 Java 内存模型（Java Memory Model，JMM）给可见性与原子性划定的边界，会用 `java.util.concurrent` 的线程池与 `CompletableFuture` 组织并发任务，并知道 JDK 21 虚拟线程解决了什么问题、没解决什么问题。

## 核心概念

线程是 JVM 调度的最小单位，每个线程有自己的栈，**堆与静态区共享**。共享可变状态是并发问题的根源。JMM 规定：没有同步时，一个线程的写入不保证对另一线程可见，于是需要 `volatile`（保证可见性与有序性，不保证原子性）或 `synchronized`（互斥 + 可见性）。

`i++` 不是原子操作，它包含读、加、写三步。计数器场景用 `AtomicInteger` 的 CAS（Compare-And-Swap）比加锁更轻。锁的粒度要小，但过小的锁会带来更多上下文切换；更要避免在持锁期间做 IO 或调用外部服务。

`Thread` 的 `start()` 才是启动新线程，直接调 `run()` 只是普通方法调用。`Thread.sleep` 会响应中断并抛 `InterruptedException`，捕获后应恢复中断标志 `Thread.currentThread().interrupt()`，否则上层无法感知取消。

线程池（thread pool）解决线程创建成本与数量失控。`Executors.newFixedThreadPool` 使用无界队列，任务积压时会 OOM；生产环境通常直接 `new ThreadPoolExecutor(...)` 明确核心数、最大数、队列与拒绝策略。JDK 19 起 `ExecutorService` 实现 `AutoCloseable`，`close()` 会等待已提交任务结束。

**虚拟线程**（Virtual Threads，Java 21 正式，JEP 444）由 JVM 而非操作系统调度，阻塞时自动卸载载体线程（carrier thread），因此可以创建上百万个。它适合**阻塞式 IO 密集**任务，不适合 CPU 密集任务，也不能靠它解决 `synchronized` 内的阻塞问题（会钉住载体线程）。

`CompletableFuture` 用于编排异步任务，`thenApply` 做同步变换、`thenCompose` 串接返回 `CompletionStage` 的操作、`thenCombine` 合并两个结果。默认使用 `ForkJoinPool.commonPool()`，IO 密集任务应传入自定义 `Executor`。

JMM 的核心是 **happens-before** 关系：解锁先于后续加锁、`volatile` 写先于后续读、线程 `start()` 先于线程内所有操作、线程内操作先于其他线程 `join()` 返回。满足这些关系时前一个操作的写入才可见，否则一切皆可能。

死锁需要四个条件同时成立：互斥、持有并等待、不可抢占、循环等待。工程上最容易破坏的是循环等待——给所有锁定义全局顺序并按序获取。排查时 `jstack` 会直接打印 `Found one Java-level deadlock` 并给出涉事线程。

`ThreadLocal` 在虚拟线程下要谨慎：每个虚拟线程都有独立副本，任务量大时可能造成内存膨胀，线程池复用时又可能带来脏数据，用完必须 `remove()`。

## 代码示例

可见性、原子性与中断的正确写法：

```java
import java.util.concurrent.atomic.AtomicInteger;

public class CounterDemo {
    private final AtomicInteger count = new AtomicInteger();
    private volatile boolean running = true;

    void increment() {
        count.incrementAndGet();            // CAS，无需加锁
    }

    void stop() {
        running = false;                    // volatile 写，其他线程可见
    }

    void loop() throws InterruptedException {
        while (running) {
            Thread.sleep(10);               // 阻塞可被中断
        }
        System.out.println("循环结束，count = " + count.get());
    }

    public static void main(String[] args) throws InterruptedException {
        CounterDemo demo = new CounterDemo();
        Thread worker = new Thread(() -> {
            try {
                demo.loop();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();   // 恢复中断标志
                System.out.println("被中断退出");
            }
        });
        worker.start();
        for (int i = 0; i < 1000; i++) {
            demo.increment();
        }
        demo.stop();
        worker.join();
    }
}
```

线程池 + `Callable` + `Future`，用 try-with-resources 保证关闭：

```java
import java.util.List;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

public class PoolDemo {
    public static void main(String[] args) throws InterruptedException {
        Callable<Long> slow = () -> {
            Thread.sleep(100);
            return 21L * 2;
        };

        try (ExecutorService pool = Executors.newFixedThreadPool(2)) {   // Java 19+
            List<Future<Long>> futures = pool.invokeAll(List.of(slow, slow, slow));
            long total = 0;
            for (Future<Long> future : futures) {
                try {
                    total += future.get();
                } catch (ExecutionException e) {
                    System.out.println("任务失败: " + e.getCause());
                }
            }
            System.out.println("合计 = " + total);
        }
    }
}
```

虚拟线程：同样的阻塞式代码，吞吐量按数量级提升：

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.stream.IntStream;

public class VirtualThreadDemo {
    public static void main(String[] args) throws InterruptedException {
        AtomicInteger done = new AtomicInteger();

        try (ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
            IntStream.range(0, 10_000).forEach(i -> pool.submit(() -> {
                Thread.sleep(10);                 // 阻塞不占用载体线程
                done.incrementAndGet();
                return null;
            }));
        }                                          // close() 等待全部任务结束

        System.out.println("完成任务数 = " + done.get());
    }
}
```

需要把「一组相关子任务」当作一个整体取消时，JDK 21 提供了 `StructuredTaskScope`，但它是**预览特性**（JEP 453），需要 `--enable-preview`，生产代码暂不建议依赖。

## 常见坑

- **用 `volatile` 保护复合操作**：`volatile int i; i++` 仍会丢更新。
- **线程池用无界队列**：`newFixedThreadPool` + 大量任务 = OOM，需有界队列与拒绝策略。
- **`Future.get()` 无超时**：下游卡死会拖垮调用方，应使用 `get(timeout, unit)`。
- **`CompletableFuture` 用 `join()` 混用异常处理**：`join` 抛 `CompletionException`，与 `get` 的 `ExecutionException` 不同。
- **虚拟线程里用 `synchronized` 长时间阻塞**：会钉住载体线程（pinning），改用 `ReentrantLock`。
- **`Thread.stop`/`suspend`**：已废弃且不安全，用中断与标志位协作取消。
