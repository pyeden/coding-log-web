# 01 环境与工具链

## 本章目标

装好 Go 并能解释 `go env` 的关键字段，分清 `go run`、`go build`、`go install` 的差别，创建一个可复现的模块，并让 `gofmt` 与 `go vet` 成为日常习惯。

## 安装与 go env

从 go.dev/dl 下载对应平台的安装包，安装后 `go version` 应输出类似 `go version go1.21.5 darwin/arm64` 的信息。Go 自带完整工具链，不需要额外构建系统。

`go env` 打印所有环境变量，最常看的有：

- `GOROOT`：Go 安装目录，通常不需要手动设置。
- `GOPATH`：旧式工作区目录，默认 `$HOME/go`；`go install` 的二进制落在 `$GOPATH/bin`。
- `GOMODCACHE`：模块下载缓存，默认 `$GOPATH/pkg/mod`，可安全删除后重新下载。
- `GOOS` / `GOARCH`：目标平台，交叉编译时通过环境变量覆盖。
- `GOPROXY`：模块代理，默认指向 proxy.golang.org，国内可按官方文档配置镜像。

首次拉取依赖时会访问 `GOPROXY` 并校验 `GOSUMDB`。公司私有仓库应设置 `GOPRIVATE`，让对应模块绕过公共代理与校验和数据库；这些配置用 `go env -w` 写入用户级配置，改动前先确认影响范围。

不要把项目放进 `GOPATH/src`——那是 GOPATH 模式的历史包袱。现代 Go 使用**模块**（module），项目可以放在任意目录。

## 运行、构建与安装

```bash
go mod init example.com/hello    # 初始化模块，生成 go.mod
go run .                         # 编译并运行，不保留产物
go build -o bin/hello .          # 生成可执行文件
go install example.com/hello@latest  # 安装到 GOBIN/GOPATH/bin
```

`go run` 适合开发期快速验证，`go build` 用于产出交付物，`go install` 安装带版本的可执行程序。`go build ./...` 构建当前模块下所有包，`go test ./...` 运行所有测试。

## 第一个程序

```go
package main

import (
	"fmt"
	"runtime"
)

func main() {
	fmt.Println("Go:", runtime.Version())
	fmt.Println("OS/Arch:", runtime.GOOS, runtime.GOARCH)
	fmt.Println("NumCPU:", runtime.NumCPU())
}
```

`package main` 与 `func main()` 是可执行程序的入口约定。导入的包必须被使用，否则编译失败——这不是风格建议，而是语言规则。`goimports` 可以自动增删导入，比手动维护省事。

## 构建信息

发布二进制时，知道它由哪个提交构建很重要。标准库 `runtime/debug` 可以读取嵌入的构建信息：

```go
package main

import (
	"fmt"
	"runtime/debug"
)

func main() {
	info, ok := debug.ReadBuildInfo()
	if !ok {
		fmt.Println("构建信息不可用")
		return
	}
	fmt.Println("模块:", info.Main.Path)
	for _, setting := range info.Settings {
		if setting.Key == "vcs.revision" {
			fmt.Println("提交:", setting.Value)
		}
	}
}
```

`go build` 在 Git 仓库内会自动嵌入版本控制信息；用 `go run` 时字段可能为空，这是正常现象。

## 格式化与静态检查

`gofmt` 是官方格式化器，没有配置项，所有 Go 代码长成一样，评审时不必争论缩进。`go vet` 检查可疑构造，例如错误的 `Printf` 格式、不可达代码、锁的复制。

```bash
gofmt -l .          # 列出未格式化的文件
gofmt -w .          # 就地格式化
go vet ./...        # 静态检查
```

编辑器保存时自动运行 `gofmt`，CI 中用 `gofmt -l` 断言输出为空，是最省事的风格约束。`go vet` 不需要额外配置，升级 Go 后应重新跑一遍，新版本常会加入更有价值的检查项。

## 工作区与多模块

一个仓库包含多个模块时，可以用 `go work init` 创建 `go.work`（Go 1.18+），把本地模块联合起来开发，避免反复写 `replace`。`go.work` 属于本地开发配置，通常不提交，或者提交时明确团队约定。

## 常见坑

- **`go run` 后找不到二进制**：它本来就不输出文件，需要产物请用 `go build`。
- **在错误的目录执行命令**：`go build` 只处理当前模块，先确认 `go env GOMOD` 指向预期文件。
- **手动设置 GOROOT**：多数情况下有害，升级 Go 后容易指向旧版本。
- **忽略 `go vet` 警告**：格式字符串不匹配这类问题运行期才炸，成本更高。
- **提交 `bin/` 与缓存**：构建产物和 `GOMODCACHE` 不应进版本库。
