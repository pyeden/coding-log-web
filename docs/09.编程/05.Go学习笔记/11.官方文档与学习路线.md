# 11 官方文档与学习路线

## 本章目标

建立 Go 官方文档的地图，知道遇到语法、标准库、工程问题分别查哪里，并给出一份四周可执行的学习路线与排错方法。

## 文档地图

- **Tour of Go**（go.dev/tour）：交互式入门，覆盖语法、方法与并发，适合第一遍建立直觉。
- **Effective Go**（go.dev/doc/effective_go）：官方风格指南，解释「为什么这样写」，不是 API 手册。
- **Language Spec**（go.dev/ref/spec）：语言语义的最终依据，边界行为以它为准。
- **pkg.go.dev**：标准库与第三方包的 API 文档，含示例与版本信息。
- **Go Blog**（go.dev/blog）：版本特性、设计决策与实战文章，1.21/1.22 的变更说明都在这里。
- **go.dev/doc**：安装、模块、教程与常见问题。

查 API 用 pkg.go.dev，查「能不能这样写」用 Spec，查「应该怎么写」用 Effective Go。三者职责不同，混用会浪费时间。

文档默认展示最新稳定版，查旧版本时注意页面顶部的版本选择器；升级前先读 Release Notes（go.dev/doc/devel/release），每个版本的行为变更都有明确条目。

## 本地文档与工具

`go doc` 直接在终端查看包文档，`go doc fmt.Println` 看单个符号；`godoc` 可启动本地文档服务（旧版本工具，现多用 pkg.go.dev）。源码本身就是最好的文档：标准库安装在 `GOROOT/src`，随时可读。

```go
// Package demo 演示 godoc 注释的写法。
package demo

// Config 保存服务配置。
type Config struct {
	Addr string // 监听地址
}

// Default 返回一份默认配置。
func Default() Config {
	return Config{Addr: ":8080"}
}
```

包注释写在 `package` 前，导出符号的注释以符号名开头，`go doc` 会据此生成可读文档。注释是 API 的一部分，修改行为时同步更新。

## 标准库速查

- 文本：`strings`、`strconv`、`unicode/utf8`、`regexp`
- 数据：`encoding/json`、`encoding/csv`、`sort`、`slices`（1.21+）、`maps`（1.21+）
- 时间：`time`
- 文件与路径：`os`、`io`、`io/fs`、`path/filepath`、`embed`
- 网络：`net/http`、`net/url`、`net`
- 并发：`sync`、`context`、`runtime`
- 测试与诊断：`testing`、`runtime/pprof`、`log/slog`（1.21+）
- 加密与编码：`crypto/*`、`encoding/base64`

标准库覆盖了大多数服务端需求，引入第三方库前先确认标准库是否够用。

## 四周学习路线

```go
package main

import (
	"fmt"
	"sort"
)

func main() {
	plan := map[string][]string{
		"第1周": {"基础语法", "切片与映射"},
		"第2周": {"结构体与接口", "错误处理"},
		"第3周": {"并发", "泛型与标准库"},
		"第4周": {"测试与性能", "小项目"},
	}

	weeks := make([]string, 0, len(plan))
	for week := range plan {
		weeks = append(weeks, week)
	}
	sort.Strings(weeks)

	for _, week := range weeks {
		fmt.Println(week, plan[week])
	}
}
```

每周配一个交付物：第一周写命令行工具，第二周拆包并加错误处理，第三周做并发抓取或 HTTP 服务，第四周补测试、基准与 CI。没有产出的学习很难转化为能力。

## 排错与提问

1. 读完整错误信息，Go 的编译错误通常直接指出文件、行号与期望类型。
2. 用 `go build ./...` 确认是编译问题还是运行问题；编译错误优先修最早的一条。
3. 运行期问题加 `-race`，并发 bug 先用竞态检测器排除。
4. 性能问题先 pprof，不要凭直觉改代码。
5. 提问附上最小可复现代码、`go version`、`go env GOOS GOARCH` 与完整错误输出。

## 推荐工具链

- 编辑器：VS Code + Go 扩展，或 GoLand；保存时 `gofmt` + `goimports`。
- 静态检查：`go vet` + `staticcheck`。
- 测试：标准库 `testing`，需要断言库时选轻量的 `testify`。
- 依赖：Go Modules，定期 `go list -m -u all` 检查更新。
- CI：固定 Go 版本，缓存模块，跑格式、vet、测试、`-race`。

## 常见坑

- **只看 Tour 不看 Spec**：遇到边界行为（切片容量、接口 nil）会判断错误。
- **照抄过时博客**：Go 1.22 改了循环变量语义，旧结论可能已失效。
- **追新特性**：`slices`、`for range int` 需要 1.21/1.22，先看 `go.mod` 的版本。
- **收藏代替实践**：文档要配合代码与项目才有用。
