# 06 面向对象与数据模型

## 本章目标

理解类与实例的属性查找顺序，会用 `property`、`dataclass` 和抽象基类表达约束，并知道什么时候该用组合而不是继承。

## 类与实例属性

类体中的赋值创建**类属性**，`__init__` 中通过 `self.x = ...` 创建**实例属性**。查找时先实例字典，再类及基类；方法本质是定义在类上的函数，通过描述符协议在访问时绑定 `self`。

可变类属性会被所有实例共享，这是新手最容易犯的错误：

```python
class Team:
    members = []            # 错误：所有实例共享

    def add(self, name):
        self.members.append(name)

a, b = Team(), Team()
a.add("alice")
print(b.members)            # ['alice']
```

正确做法是在 `__init__` 里为每个实例创建独立列表。与实例方法并列的还有两类方法：`@classmethod` 的第一个参数是类（常用于替代构造器，如 `from_dict`），`@staticmethod` 不接收隐式参数（本质上是命名空间里的普通函数），二者都不需要实例即可调用。

## 继承与 super

`class Child(Base)` 建立继承关系，`super()` 按 MRO（方法解析顺序）调用下一个实现。多继承时务必使用 `super().__init__()` 协作式初始化，而不是显式写死父类名。Python 支持多继承，但菱形继承会放大复杂度，通常用 mixin 表达「可叠加的能力」。

```python
class Animal:
    def __init__(self, name: str) -> None:
        self.name = name

    def speak(self) -> str:
        raise NotImplementedError

class Dog(Animal):
    def speak(self) -> str:
        return f"{self.name}: 汪"

print(Dog("旺财").speak())
```

## property 与受控属性

`@property` 把方法伪装成属性，用于校验、惰性计算或保持向后兼容。配套的 `@x.setter` 定义赋值逻辑。注意属性名与内部字段不要同名，否则无限递归。属性适合「便宜且无副作用」的计算；如果一次读取要发网络请求，保留显式方法更能提醒调用方代价。

```python
class Temperature:
    def __init__(self, celsius: float) -> None:
        self._celsius = 0.0
        self.celsius = celsius

    @property
    def celsius(self) -> float:
        return self._celsius

    @celsius.setter
    def celsius(self, value: float) -> None:
        if value < -273.15:
            raise ValueError("低于绝对零度")
        self._celsius = value

t = Temperature(25)
print(t.celsius)      # 25
```

## dataclass

`@dataclass` 根据字段注解自动生成 `__init__`、`__repr__`、`__eq__`。`frozen=True` 生成不可变对象（可哈希），`slots=True`（3.10+）减少内存占用，`field(default_factory=list)` 解决可变默认值问题。

```python
from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True)
class Point:
    x: float
    y: float

@dataclass
class Order:
    order_id: str
    items: list[str] = field(default_factory=list)

print(Point(1, 2))
print(Order("A1", ["book"]))
```

需要严格校验时用 `pydantic` 等第三方库；标准库 dataclass 只做结构生成，不做类型检查。`__post_init__` 可以补充校验逻辑，`field(compare=False)` 让某字段不参与相等比较。注意 `frozen=True` 的对象虽然不可变，但这只是禁止属性赋值，内部可变字段仍可能被修改。

## 特殊方法与数据模型

`__str__` 面向用户、`__repr__` 面向开发者（理想情况下可用来重建对象），`__eq__` 定义相等语义，`__hash__` 决定能否作为字典键。定义了 `__eq__` 而未定义 `__hash__` 时，实例会变为不可哈希。`__len__`、`__iter__`、`__getitem__`、`__enter__/__exit__` 让对象融入语言协议，这比提供一堆 `get_x()` 方法更自然。

## 抽象基类与组合

`abc.ABC` + `@abstractmethod` 在实例化时强制子类实现方法，适合表达接口契约；`typing.Protocol` 则提供结构化子类型（见第 09 章）。二者都不是必须的，小项目用文档约定也可行。

「组合优于继承」的含义是：把能力拆成独立对象并持有引用，而不是堆继承层级。继承适合真正的「is-a」关系，组合适合「has-a」。当子类只需要父类的一两个方法时，通常说明该用组合。

## 常见坑

- **可变类属性当实例状态**：见上例，用 `__init__` 隔离。
- **忘记调用 `super().__init__()`**：父类状态未初始化，错误出现得很晚。
- **在 `__init__` 里做重 IO**：对象构造应轻量，副作用放到显式方法。
- **`__repr__` 返回非字符串**：会抛 `TypeError`。
- **过度继承**：层级超过三层就该重新审视设计。
