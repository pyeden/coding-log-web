# 11 官方文档导航与学习路线

## 本章目标

把 `docs.python.org` 从「查函数的地方」变成可系统阅读的手册，知道遇到问题该翻哪一册，并给出一份可执行的四周学习路线。

## 文档的四块地图

官方文档按用途分为四部分，中文版与英文版结构一致：

| 部分 | 内容 | 什么时候读 |
| --- | --- | --- |
| Tutorial（教程） | 语言入门，按主题递进 | 第一次系统学习 |
| Library Reference（库参考） | 标准库逐模块说明 | 查 API 细节 |
| Language Reference（语言参考） | 语法与语义的正式定义 | 搞不清边界行为 |
| HOWTO / FAQ | 专题指南与常见问题 | 解决具体场景 |

三者的差别很关键：教程告诉你「怎么用」，库参考告诉你「参数与返回值」，语言参考告诉你「为什么这样」。「Python 的 for 为什么不会越界」「装饰器求值顺序」这类问题，答案通常在语言参考而不是教程。

## 高效查阅的方法

1. **先看目录页**：`library/index.html` 有按字母与按主题两种索引，比搜索更快建立全局印象。
2. **用 `help()` 和 `pydoc`**：本地文档与版本严格对应，离线可用。
3. **注意版本标注**：文档中「Added in version 3.11」「Changed in version 3.12」是判断兼容性的第一手依据。
4. **读源码**：标准库是纯 Python 的重灾区也是最好的教材，`inspect.getsource` 可直接打印。

```python
import inspect
import json
import pydoc

print(pydoc.render_doc("json.dumps", renderer=pydoc.plaintext)[:300])
print(inspect.signature(json.dumps))
print(inspect.getsource(json.dumps)[:200])
```

`pydoc` 的输出就是本地文档的纯文本版；`inspect` 能拿到签名、源码位置与注解。把 `json.dumps` 换成你正在用的函数，就能在不离开终端的情况下看到它接受什么参数、内部怎么实现。

## 标准库速查

不必背全，按场景建立索引即可：

- **文件与路径**：`pathlib`、`os`、`shutil`、`tempfile`
- **文本与数据**：`json`、`csv`、`re`、`string`、`textwrap`
- **时间**：`datetime`、`zoneinfo`、`time`
- **容器与算法**：`collections`、`heapq`、`bisect`、`itertools`、`functools`
- **系统与进程**：`sys`、`subprocess`、`argparse`、`signal`
- **并发**：`threading`、`multiprocessing`、`concurrent.futures`、`asyncio`
- **网络**：`urllib.request`、`http.client`、`socket`、`ssl`
- **调试与测试**：`logging`、`pdb`、`unittest`、`doctest`、`timeit`、`cProfile`
- **持久化**：`sqlite3`、`pickle`、`dbm`

第三方生态里，`requests`/`httpx`、`pydantic`、`pytest`、`ruff` 已成为事实标准，但标准库仍是零依赖场景的底线。

## 四周学习路线

```python
plan = {
    "第 1 周": ["环境与 venv", "语法、字符串、容器", "控制流与函数"],
    "第 2 周": ["模块与包", "面向对象", "异常与日志"],
    "第 3 周": ["标准库实战", "类型注解", "pytest 与工具链"],
    "第 4 周": ["并发与 asyncio", "性能剖析", "完成一个小项目"],
}

for week, topics in plan.items():
    print(week + "：" + "、".join(topics))
```

每周配一个可交付物：第一周写命令行小工具，第二周拆成包并加测试，第三周接入真实数据（CSV/JSON/SQLite），第四周做并发抓取或异步服务。**没有产出的学习会迅速蒸发**。

## 排错与提问方法

遇到报错按这个顺序处理：

1. 读最后一行异常类型与消息，再读最上面一帧自己的代码。
2. 用最小复现剥离无关代码；能稳定复现就成功了一半。
3. 查文档的「Changed in version」，确认是否版本差异。
4. 搜索时带上完整错误消息与版本号，优先看官方 issue 与 Stack Overflow 高票答案。
5. 提问附上：目标、最小代码、完整 traceback、Python 版本与操作系统。缺少这些信息的问题很难得到有效回答。

## 推荐工具链

- **解释器管理**：pyenv 或系统包管理器，项目内固定次版本。
- **环境与依赖**：venv + pip，或 uv（速度快，兼容 pyproject）。
- **格式化与 lint**：ruff（format + lint 一体）。
- **类型检查**：mypy 或 pyright，新项目开严格模式。
- **测试**：pytest + pytest-cov。
- **提交前检查**：pre-commit。
- **编辑器**：VS Code + Pylance，或 PyCharm，关键是开启保存即格式化与类型提示。

## 常见坑

- **只看教程不看库参考**：参数默认值、异常类型全靠猜。
- **照抄过时博客**：Python 3.12 已移除或弃用的写法仍在流传，以官方文档为准。
- **追新语法**：`match`、`TaskGroup` 很好，但团队环境可能是 3.9，先确认 `requires-python`。
- **收藏代替阅读**：收藏夹不会自动变成能力，按路线执行才有用。
