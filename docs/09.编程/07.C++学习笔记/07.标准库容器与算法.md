# 07 标准库容器与算法

## 本章目标

熟悉常用容器的语义、复杂度与迭代器失效规则，能用 `<algorithm>` 与 `<numeric>` 替代手写循环。学完本章，你应该能根据访问模式与数据规模选对容器，并写出不会踩迭代器失效的删除逻辑。

## 核心概念

容器（container）管理元素存储与生命周期；迭代器（iterator）是算法访问容器的统一接口；复杂度（complexity）描述操作随规模增长的趋势；迭代器失效（iterator invalidation）指容器结构变化后旧迭代器不再可用，是容器误用的头号原因。

## 顺序容器

`std::vector` 是默认选择：连续内存、随机访问 O(1)、尾部插入摊还 O(1)、中间插入 O(n)。`std::array` 是固定长度的栈上数组，大小必须是编译期常量，没有堆分配。`std::string` 本质是字符容器，`std::deque` 支持两端高效插入，`std::list` 只在确实需要 O(1) 中间插入/拼接时才考虑——它的节点分散，遍历缓存不友好，实践中很少比 `vector` 快。

容量（capacity）与大小（size）要分清：`reserve` 预留容量避免反复扩容，`resize` 改变元素个数。`shrink_to_fit` 只是请求，不保证生效。

```cpp
#include <algorithm>
#include <array>
#include <iostream>
#include <iterator>
#include <string>
#include <vector>

int main() {
    std::vector<int> xs{5, 3, 9, 1};
    std::sort(xs.begin(), xs.end());
    auto it = std::find(xs.begin(), xs.end(), 5);
    std::cout << std::distance(xs.begin(), it) << '\n';

    std::array<int, 3> a{1, 2, 3};
    std::string s = "hello";
    s += ", world";
    std::cout << a.size() << ' ' << s.size() << '\n';
}
```

## 关联容器

`std::map` / `std::set` 基于平衡树，有序、查找 O(log n)；`std::unordered_map` / `std::unordered_set` 基于哈希表，平均 O(1)，但无序且最坏情况退化。需要按 key 有序遍历用 `map`，只做存在性查询与计数用 `unordered_map`。

`operator[]` 在 key 不存在时会**插入**默认值，这是统计代码里最常见的意外；只读查询用 `find`（C++20 起可用 `contains`，C++17 请写 `find(...) != end()`）。`at` 越界抛 `std::out_of_range`，适合「缺失即错误」的场景。

```cpp
#include <iostream>
#include <map>
#include <set>
#include <string>
#include <unordered_map>

int main() {
    std::map<std::string, int> ordered{{"b", 2}, {"a", 1}};
    std::unordered_map<std::string, int> hashed{{"x", 1}};
    std::set<int> unique{3, 1, 3};

    ordered["c"] = 3;
    auto it = hashed.find("x");
    std::cout << ordered.begin()->first << ' '
              << (it != hashed.end() ? it->second : -1) << ' '
              << unique.size() << '\n';
}
```

## 迭代器与失效规则

迭代器是容器与算法之间的契约。`vector` 在扩容时所有迭代器、指针、引用失效；`erase` 使被删元素及其后的迭代器失效。`map` / `set` 的 erase 只使被删节点失效，其他节点稳定——这是节点式容器的重要优势。

删除满足条件的元素，C++17 的写法是用 `erase` 的返回值推进迭代器：

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> xs{1, 2, 3, 4, 5, 6};
    for (auto it = xs.begin(); it != xs.end();) {
        if (*it % 2 == 0) {
            it = xs.erase(it);      // 返回下一个有效迭代器
        } else {
            ++it;
        }
    }
    for (int x : xs) { std::cout << x << ' '; }
    std::cout << '\n';
}
```

C++20 的 `std::erase_if` 把这个模式封装成一行，但 C++17 项目需要上面的写法。不要写 `for (auto it : xs) xs.erase(...)`，那必然失效。

## 算法与数值

`<algorithm>` 提供排序、查找、变换、计数、最值等通用算法，配合 lambda 谓词几乎能表达所有遍历需求。优先用算法而不是手写循环：意图更明确，也更容易被优化。`<numeric>` 提供 `accumulate`、`partial_sum`、`iota`、`gcd` 等数值操作。

```cpp
#include <iostream>
#include <numeric>
#include <vector>

int main() {
    std::vector<int> xs{1, 2, 3, 4};
    int total = std::accumulate(xs.begin(), xs.end(), 0);
    std::vector<int> prefix(xs.size());
    std::partial_sum(xs.begin(), xs.end(), prefix.begin());
    std::cout << total << ' ' << prefix.back() << '\n';
}
```

注意 `accumulate` 的初值类型决定累加类型：`0` 是 `int`，对 `double` 序列求和会丢精度，应写 `0.0`。C++17 还提供并行算法重载（`std::execution::par`），但需要链接 TBB 等后端，属于可选能力。

## 复杂度与选型

- 默认 `vector`；只在需要稳定节点与 O(1) 拼接时考虑 `list`。
- 需要有序遍历或范围查询 → `map` / `set`。
- 只需快速查找 → `unordered_*`，并预留桶数减少 rehash。
- 固定大小且生命周期短 → `array`。
- 字符串拼接多 → 先 `reserve`，避免反复分配。
- C++20 ranges 让 `views::filter` / `transform` 可以惰性组合，但 C++17 项目请用算法 + lambda。

选择容器前先估计数据规模与访问模式：十万级以内的有序数据，`map` 与 `unordered_map` 的差距常被常数因子掩盖；真正的瓶颈往往是内存分配与缓存未命中，而不是渐近复杂度。

## 常见坑 / 最佳实践

- 不要在范围 for 中修改容器结构（增删元素）。
- `vector` 扩容后旧指针全部失效，不要在扩容前缓存 `&v[0]`。
- `map::operator[]` 会插入，只读场景用 `find` / `at`。
- `erase` 用返回值推进迭代器，或使用 C++20 `erase_if`。
- 传谓词给算法时避免捕获失效的引用。
- 容器存多态对象要用 `unique_ptr`，不能按值存基类（会切片）。
