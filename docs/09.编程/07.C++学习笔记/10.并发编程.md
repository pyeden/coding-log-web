# 10 并发编程

## 本章目标

掌握 C++11 起的线程、互斥量、条件变量与原子操作，能识别数据竞争（data race）与死锁（deadlock）。学完本章，你应该能写出正确的生产者—消费者模型，并知道 `std::atomic` 的内存序（memory order）为什么不能随手写 `relaxed`。

## 核心概念

数据竞争（data race）指多线程无同步地访问同一内存且至少一方写入，属于未定义行为；互斥量（mutex）提供临界区；条件变量（condition variable）用于等待状态变化；内存序（memory order）规定原子操作之间的可见性与顺序约束。

## 线程与互斥量

`std::thread` 在构造时启动线程，必须在销毁前 `join()`（等待结束）或 `detach()`（分离），否则析构会调用 `std::terminate`。多个线程访问同一非原子变量且至少一个写，就是数据竞争，属于未定义行为。用 `std::mutex` 保护共享数据，用 RAII 的 `std::lock_guard` 自动加解锁，避免异常路径漏解锁。

```cpp
#include <iostream>
#include <mutex>
#include <thread>
#include <vector>

int main() {
    long counter = 0;
    std::mutex m;
    std::vector<std::thread> workers;

    for (int i = 0; i < 4; ++i) {
        workers.emplace_back([&] {
            for (int k = 0; k < 1000; ++k) {
                std::lock_guard<std::mutex> lock(m);
                ++counter;
            }
        });
    }

    for (auto& t : workers) { t.join(); }
    std::cout << counter << '\n';
}
```

锁的粒度要权衡：锁内做 I/O 或长计算会严重串行化；锁外访问共享数据又会竞争。经验是「锁只保护数据，不保护逻辑」。

线程数量也不是越多越好：创建线程与上下文切换都有成本，CPU 密集任务通常设为硬件并发数（`std::thread::hardware_concurrency()`），I/O 密集任务才考虑更高并发。并发代码上线前用 ThreadSanitizer 跑一遍测试，比事后排查偶发崩溃便宜得多。

## 条件变量

条件变量（condition variable）用于线程间等待某个条件成立。等待必须放在循环或带谓词的 `wait` 中，以应对虚假唤醒（spurious wakeup）。修改条件时必须持锁，`notify_one` / `notify_all` 可以在解锁后调用以减少唤醒后的立即阻塞。

```cpp
#include <condition_variable>
#include <iostream>
#include <mutex>
#include <queue>
#include <thread>

int main() {
    std::queue<int> q;
    std::mutex m;
    std::condition_variable cv;
    bool done = false;

    std::thread producer([&] {
        for (int i = 0; i < 3; ++i) {
            {
                std::lock_guard<std::mutex> lock(m);
                q.push(i);
            }
            cv.notify_one();
        }
        {
            std::lock_guard<std::mutex> lock(m);
            done = true;
        }
        cv.notify_all();
    });

    std::thread consumer([&] {
        for (;;) {
            std::unique_lock<std::mutex> lock(m);
            cv.wait(lock, [&] { return !q.empty() || done; });
            while (!q.empty()) {
                int v = q.front();
                q.pop();
                lock.unlock();
                std::cout << v << '\n';
                lock.lock();
            }
            if (done) { break; }
        }
    });

    producer.join();
    consumer.join();
}
```

`std::unique_lock` 比 `lock_guard` 灵活：可延迟加锁、可手动解锁、可转移所有权，条件变量要求使用它。

## 原子操作与内存序

`std::atomic<T>` 提供不可分割的读改写，避免数据竞争。默认内存序是 `memory_order_seq_cst`（顺序一致），最直观也最慢；`acquire` / `release` 用于建立同步关系，`relaxed` 只保证原子性、不保证可见顺序。除非你在实现无锁数据结构，否则不要用 `relaxed` 同步共享状态。

```cpp
#include <atomic>
#include <future>
#include <iostream>

int main() {
    std::atomic<int> value{0};
    auto fut = std::async(std::launch::async, [&] {
        value.fetch_add(1, std::memory_order_relaxed);
        return value.load(std::memory_order_relaxed);
    });
    std::cout << fut.get() << '\n';
}
```

`std::async` 返回 `std::future`，`get()` 会等待任务完成并取出结果（只能调用一次）。注意 `std::async` 不指定 `std::launch::async` 时可能延迟执行，甚至在 `future` 析构时同步等待，行为不够直观，生产代码建议显式指定策略。

## 死锁与线程池

死锁的四个必要条件里，最容易控制的是「持有并等待」。规避手段：

- 固定加锁顺序，所有线程按同一顺序获取多个锁。
- 用 `std::scoped_lock`（C++17）一次锁定多个互斥量，内部使用避免死锁的算法。
- 缩小临界区，尽量不在持锁时调用外部代码。
- 用 `std::lock_guard` / `unique_lock` 保证异常安全。

线程池（thread pool）的核心是「任务队列 + 固定工作线程 + 条件变量」，避免为每个任务创建线程。生产环境优先使用成熟库（如 TBB、folly），不要手写调度器。

C++20 引入 `std::jthread`，析构时自动 `join`，并支持 `std::stop_token` 协作式取消；C++20 还提供 `std::counting_semaphore`、`std::latch`、`std::barrier`。C++17 项目需要自行封装或用第三方库。

## 常见坑 / 最佳实践

- 线程对象必须 `join` 或 `detach`，否则析构终止进程。
- 用 RAII 管理锁，不要手写 `lock()` / `unlock()`。
- `condition_variable::wait` 必须带谓词或放在循环里。
- 不要在持锁时调用可能回调用户代码的函数（死锁温床）。
- `volatile` 不是同步原语，跨线程通信用 `atomic` 或互斥量。
- 优先「消息传递 / 任务队列」而非共享可变状态。
