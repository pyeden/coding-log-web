# 09 类型注解与测试工程化

## 本章目标

用类型注解表达接口契约，让静态检查在运行前发现错误；用 pytest 与覆盖率把「能跑」变成「可验证」，并用工具链统一代码风格。

## 类型注解基础

注解只是**元数据**，运行时默认不校验，但可被 IDE、mypy、pydantic 等读取。3.10+ 推荐 `int | None`，等价于 `Optional[int]`；`list[str]`、`dict[str, int]` 从 3.9 起可直接作泛型。

```python
from collections.abc import Iterable
from typing import Optional, Union

def total(values: Iterable[float]) -> float:
    return sum(values)

def find_user(uid: int) -> Optional[dict[str, str]]:
    return {"id": str(uid)} if uid > 0 else None

def parse(value: Union[int, str]) -> int:
    return value if isinstance(value, int) else int(value)
```

`Any` 会关闭检查，应尽量避免；`object` 表示「任意类型但必须先窄化」。`TypedDict` 描述固定键的字典，`Literal` 限定取值集合，`Final` 标记不可重新赋值。一个实用原则：**公共函数必须写返回类型**，内部短函数可以按需省略，因为返回值是接口契约中最容易被误用的部分。

## Protocol 与泛型

`Protocol` 实现结构化子类型：只要对象有对应方法就满足协议，不需要显式继承。适合为第三方库对象写接口，避免侵入式改造。

```python
from pathlib import Path
from typing import Protocol, TypeVar

class Reader(Protocol):
    def read(self) -> str: ...

def load(reader: Reader) -> str:
    return reader.read()

T = TypeVar("T")

def first(items: list[T]) -> T:
    if not items:
        raise ValueError("空列表")
    return items[0]

print(first([1, 2, 3]))
with Path(__file__).open(encoding="utf-8") as fh:
    print(load(fh)[:20])
```

3.12 起可用 `class Reader(Protocol):` 配合 `type` 语句定义别名；泛型也可写成 `def first[T](items: list[T]) -> T`，但为兼容性与工具支持，`TypeVar` 仍是稳妥选择。

## 静态检查与格式化

- **mypy**：老牌类型检查器，`mypy src` 即可；严格模式 `strict = true` 建议新项目直接开启。
- **pyright**：微软实现，速度快，VS Code 的 Pylance 基于它。
- **ruff**：Rust 写的 linter + formatter，覆盖 pycodestyle、pyflakes、isort 等规则，可作为主力。
- **black**：格式化风格稳定，与 ruff format 二选一即可，不要同时跑。

在 `pyproject.toml` 集中配置，避免散落的 `setup.cfg`：

```toml
[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]

[tool.mypy]
python_version = "3.12"
strict = true

[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-q"
```

## pytest 基础

pytest 用普通函数 + `assert`，失败时自动展示表达式细节。文件名 `test_*.py`，函数名 `test_*`，fixture 通过参数注入，`parametrize` 覆盖多组输入。

```python
# tests/test_calc.py
import pytest

def divide(a: float, b: float) -> float:
    if b == 0:
        raise ZeroDivisionError("除数不能为零")
    return a / b

@pytest.mark.parametrize("a,b,expected", [(6, 3, 2.0), (1, 2, 0.5)])
def test_divide(a, b, expected):
    assert divide(a, b) == expected

def test_divide_by_zero():
    with pytest.raises(ZeroDivisionError):
        divide(1, 0)
```

`pytest --cov=src --cov-report=term-missing` 输出覆盖率（需 `pytest-cov`）。覆盖率是下限指标，不是目标：100% 覆盖仍可能漏掉逻辑错误，关键在断言质量与边界用例。写测试时优先覆盖「分支」而不是「行」：每个 `if` 的两侧、每个 `except` 的触发路径，比重复调用同一个正常用例更有价值。

## pre-commit 与 CI

`pre-commit` 在提交前自动运行检查，配置 `.pre-commit-config.yaml` 指向 ruff、mypy、trailing-whitespace 等钩子。CI 中重复执行同样命令，保证「本地通过 = 远端通过」。顺序建议：格式化 → lint → 类型检查 → 测试，失败越早越便宜。

类型检查不是一次性的：先把新代码纳入检查，再逐步修复旧模块，比一次性开启严格模式后被上千条错误淹没更可行。仓库可以在 `pyproject.toml` 里按目录覆盖规则，逐步收紧。

fixture 用来管理测试依赖：数据库连接、临时目录、环境变量都应在 fixture 中准备与清理，`yield` 之前是 setup、之后是 teardown。`tmp_path` 是 pytest 内置的临时目录 fixture，比手写 `tempfile` 更安全，因为每个测试拿到独立路径。

## 常见坑

- **注解写成字符串却忘记 `from __future__ import annotations`**：前向引用需要延迟求值；3.14 起注解默认惰性求值，但旧版本仍需注意。
- **把 `list` 当类型**：`def f(x: list) -> list` 丢失元素类型，应写 `list[str]`。
- **类型检查通过就以为没问题**：注解不校验运行时数据，外部输入仍需验证。
- **测试依赖执行顺序**：每个测试应独立，共享状态用 fixture 显式管理。
- **在 `pyproject.toml` 与 `mypy.ini` 重复配置**：两处冲突时工具行为难以预测，只保留一处。
- **测试里用真实网络或时钟**：慢且不稳定，用 fixture 注入假客户端与可控时间。
