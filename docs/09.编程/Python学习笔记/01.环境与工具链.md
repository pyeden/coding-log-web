# 01 环境与工具链

## 本章目标

把 Python 跑起来，并且分清「解释器、虚拟环境、依赖管理器」这三件事。学完本章，你应该能在同一台机器上维护多个项目的依赖而不互相污染，并知道遇到 `command not found` 或 `ModuleNotFoundError` 时从哪里查起。

## 版本与解释器

Python 由语言规范和多个实现组成。日常说的 Python 通常是 **CPython**（官方用 C 写的参考实现）。本书以 **Python 3.12 / 3.13** 为基准：3.12 引入更灵活的 f-string 解析、`type` 语句别名；3.13 带来实验性的 free-threaded 构建（可选，非默认，官方标注为实验特性，不建议直接用于生产）。

版本号形如 `3.13.1`：主版本、次版本、修订号。语言特性按次版本增加，例如 `match` 需要 3.10+，`ExceptionGroup` 需要 3.11+。判断环境时不要凭感觉，直接问解释器：

```python
import sys

print(sys.version_info[:3])
print(sys.executable)
print(sys.platform)
```

`sys.executable` 尤其重要：当 IDE、`pip` 和终端用的不是同一个解释器时，装包会「装上了却 import 不到」。另一个常被忽略的点是**不要混用系统包管理器与 pip**：macOS 的 Homebrew Python 标记为 externally-managed，直接 `pip install` 会被拒绝，这不是 bug，而是防止破坏系统工具链的保护。

## REPL、脚本与 python -m

不带参数运行 `python3` 进入交互式解释器（REPL），适合验证一行表达式；把代码写进 `.py` 文件用 `python3 main.py` 执行，适合正式开发。第三种方式常被忽略：`python3 -m 模块名`，它把模块当作脚本运行，并自动把当前目录加入 `sys.path`。

```python
# 计算器式的小验证：REPL 里也这样写
from decimal import Decimal

price = Decimal("19.90")
count = 3
print(price * count)          # 59.70，避免二进制浮点误差
print(f"总计 {price * count:.2f} 元")
```

`python3 -m json.tool data.json` 可以格式化 JSON，`python3 -m venv .venv` 创建虚拟环境，`python3 -m pip --version` 确认 pip 属于哪个解释器——`-m` 是排查环境错乱的第一把钥匙。

## venv 与 pip

虚拟环境是隔离依赖的最小手段。项目根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
python -m pip install -U pip
```

激活后 `python`、`pip` 都指向 `.venv` 内的副本，安装的包落在 `.venv/lib/.../site-packages`，不会污染系统环境。退出用 `deactivate`。不要把 `.venv` 提交到 Git。

虚拟环境目录名建议统一为 `.venv`，这样编辑器、`pre-commit`、CI 都能按约定自动发现；换机器时重建环境比拷贝目录可靠，因为 venv 里的路径和解释器版本是硬编码的。

`pip install requests` 安装包，`pip freeze > requirements.txt` 导出精确版本，`pip install -r requirements.txt` 复现。注意 `freeze` 会包含间接依赖，适合锁定而不适合表达「我直接用了什么」。

## pyproject 概览

现代 Python 项目用 `pyproject.toml` 描述构建后端、元数据和工具配置。它取代了 `setup.py` 的多数用途，也是 pip、ruff、pytest、mypy 共同读取的配置入口：

```toml
[project]
name = "demo"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = ["httpx>=0.27"]

[project.optional-dependencies]
dev = ["pytest>=8", "ruff>=0.6"]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
```

安装时 `pip install -e ".[dev]"` 会以可编辑模式装入当前项目，并带上开发依赖。

## PATH 与多版本

`PATH` 决定 shell 找到哪个 `python3`。用 `which -a python3` 可以看到全部候选。多版本共存推荐 **pyenv**：它通过 shim 目录切换全局/局部版本，`pyenv install 3.13.1`、`pyenv local 3.13.1` 即可为单个项目固定版本。Windows 上可用官方 py launcher（`py -3.12`）。

## 常见坑

- **直接用系统 Python 装包**：macOS/Linux 的系统解释器受保护，且升级系统可能清空包。永远先建 venv。
- **`python` 与 `python3` 混用**：某些发行版两者不同版本，脚本 shebang 和文档统一写 `python3`。
- **忘了激活环境**：`pip -V` 的输出路径里应出现 `.venv`，这是最快的自检。
- **锁定文件缺失**：只写 `requests` 不写版本，半年后构建结果可能完全不同。生产项目应提交锁文件。
- **在 venv 里用 `sudo pip`**：装到系统目录，且权限混乱，永远不要这么做。
- **把 `python3` 写进 shebang 却依赖激活状态**：部署脚本应使用绝对路径或显式激活环境。

## 一个最小可用的起点

新建项目时按以下顺序执行，可以避开绝大多数环境问题：确认 `python3 -V` 与 `sys.executable` → 创建 `.venv` → 升级 pip → 写 `pyproject.toml` → 可编辑安装 → 跑一次 `python3 -c "import 包名"`。这套流程不到五分钟，却能省下之后几个小时「为什么 import 失败」的排查。
