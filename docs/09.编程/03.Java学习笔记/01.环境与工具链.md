# 01 环境与工具链

## 本章目标

把 JDK 装好、把 `javac` 与 `java` 分清、把项目构建交给 Maven 或 Gradle。学完本章，你应该能独立判断「我的代码到底跑在哪个 JDK 上」，并能用一条命令验证编译目标版本。

## 核心概念

Java 的运行时由三部分组成：**JVM**（Java Virtual Machine，虚拟机）负责执行字节码；**JRE**（Java Runtime Environment）是 JVM 加核心类库；**JDK**（Java Development Kit）在 JRE 之上再加编译器与诊断工具。自 JDK 11 起官方不再单独分发 JRE，开发机一律装 JDK。

版本选择上，本笔记以 **JDK 21** 为基准。它是 LTS（Long-Term Support，长期支持）版本，也是首个正式包含虚拟线程（Virtual Threads，JEP 444）的版本。LTS 之外还有每半年一个的功能版本（feature release），如 22、23，只维护半年，适合尝鲜不适合生产。

一段 Java 源码要经过**编译**与**运行**两步：`javac` 把 `.java` 编译成平台无关的 `.class` 字节码，`java` 启动 JVM 加载字节码执行。字节码的版本号与编译时目标版本绑定，低版本 JVM 无法运行高版本字节码，这就是 `UnsupportedClassVersionError` 的来源。

三个命令要分清：`javac` 编译、`java` 运行、`jshell` 是 JDK 9 引入的交互式求值工具（REPL）。`jar` 打包、`javadoc` 生成文档、`jdeps` 分析依赖、`jcmd`/`jstack` 诊断运行时状态，都属于 JDK 自带工具链，无需额外安装。

命令行与 IDE 不是二选一。IDE 的补全与调试能提升效率，但最终交付给 CI 的是命令：谁能在干净机器上用 `javac`、`mvn` 跑通，谁的项目才算可复现。因此建议先用命令行把流程走通，再用 IDE 加速。

多版本共存时不要靠修改全局 `JAVA_HOME` 切换。macOS/Linux 可用 SDKMAN 或系统自带的 alternatives 机制按目录切换；CI 里则通过工具链声明所需 JDK（Maven Toolchains、Gradle Toolchain），让构建自己找匹配版本，而不是依赖运行者的环境变量。

构建工具的出现是为了替代手写的长命令：依赖下载、增量编译、测试执行、打包发布都由它编排。Maven 与 Gradle 的取舍在第 09 章展开，这里只需记住：**编译单元是源文件，发布单元是构件**（artifact），两者之间的映射由构建工具负责。

## 代码示例

先确认环境。`javac -version` 与 `java -version` 必须指向同一个 JDK，`JAVA_HOME` 应指向 JDK 根目录而不是 `bin`：

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)   # macOS
javac -version
java -version
```

第一个可运行程序，同时打印运行时信息：

```java
// Hello.java
public class Hello {
    public static void main(String[] args) {
        String version = System.getProperty("java.version");
        String vendor = System.getProperty("java.vendor");
        System.out.printf("运行于 JDK %s (%s)%n", version, vendor);
    }
}
```

编译运行：`javac Hello.java && java Hello`。注意生成的是 `Hello.class`，运行时写的是类名 `Hello` 而不是文件名 `Hello.class`。

多属性排查时，用集合把关键系统属性一次性输出：

```java
import java.util.Map;

public class Toolchain {
    public static void main(String[] args) {
        Map<String, String> props = Map.of(
                "java.version", System.getProperty("java.version"),
                "java.home", System.getProperty("java.home"),
                "os.arch", System.getProperty("os.arch"));
        props.forEach((k, v) -> System.out.println(k + " = " + v));
    }
}
```

`java.home` 指向的是 JRE 目录（JDK 内嵌），与 `JAVA_HOME` 不一定相同，排查「IDE 用的 JDK 和终端不是一个」时两者都要看。若只想验证某个语言特性能否在目标版本使用，编译时加 `--release`：

```java
public class ReleaseDemo {
    public static void main(String[] args) {
        // 文本块（Text Block，Java 15 正式）
        String help = """
                javac --release 17 ReleaseDemo.java
                java ReleaseDemo
                """;
        System.out.print(help);
    }
}
```

`javac --release 17` 会同时限制语言特性与 API 面，比 `-source 17 -target 17` 更严格，跨版本兼容检查应优先用它。

## 常见坑

- **`java` 与 `javac` 版本不一致**：装在 PATH 里的 `java` 可能来自另一个 JDK，`java -version` 与 `javac -version` 必须对照。
- **`JAVA_HOME` 指到 `bin`**：正确值是 JDK 根目录，很多脚本会拼 `$JAVA_HOME/bin/java`。
- **写 `java Hello.class`**：会报找不到主类，运行期参数是类名。
- **只改 `-source`**：不同步改 `-target` 会产出高版本字节码，在旧环境直接崩溃。
- **把 `jshell` 当脚本运行器**：它面向交互探索，正式代码仍应写成 `.java` 文件。
