# 04 数组、切片与映射

## 本章目标

分清数组与切片的语义差异，理解切片共享底层数组带来的影响，掌握 `append`、`copy` 与 `len/cap`，并能正确使用映射的 comma-ok 与删除操作。

## 数组与切片

数组 `[N]T` 长度是类型的一部分，赋值与传参都会**复制整个数组**。切片 `[]T` 是一个描述符：指向底层数组的指针、长度 `len` 与容量 `cap`，赋值只复制描述符，底层数据仍共享。

因此实际开发几乎总用切片，数组多用于固定长度的底层缓冲或作为 map 的键。切片可以用 `make([]T, len, cap)` 创建，容量省略时等于长度。

```go
package main

import "fmt"

func main() {
	arr := [3]int{1, 2, 3}
	slice := []int{1, 2, 3}

	slice = append(slice, 4)
	fmt.Println(arr, len(arr))
	fmt.Println(slice, len(slice), cap(slice))

	sub := slice[1:3]
	sub[0] = 99
	fmt.Println(slice) // 修改 sub 会影响 slice

	dst := make([]int, len(slice))
	n := copy(dst, slice)
	fmt.Println(dst, n)
}
```

`append` 在容量足够时复用底层数组，否则分配新数组并复制。因此 `append` 的返回值必须接收，不能假设原切片一定被修改。

扩容策略由运行时决定，具体倍数不属于语言规范，不要依赖。能预估容量时用 `make([]T, 0, n)` 一次性分配，可显著减少复制与 GC 压力。`copy` 只复制 `min(len(dst), len(src))` 个元素，返回值是实际复制的数量。

## 共享底层数组的陷阱

```go
package main

import "fmt"

func main() {
	a := make([]int, 2, 4)
	b := append(a, 3)
	c := append(a, 4)
	fmt.Println(a, b, c)
}
```

`a` 的长度是 2、容量是 4，两次 `append` 都没有扩容，`b` 与 `c` 写的是同一块内存的第三个位置，最终 `b` 也会看到 `c` 写入的 4。需要独立结果时，先复制或用 `append([]int(nil), a...)`。

另一个隐蔽问题是内存滞留：从一个大切片截取很小的一段，只要这段仍被引用，整个底层数组都不会被回收。长期存活的缓存应把需要的元素复制到新切片，而不是保留大数组的窗口。

## 映射

`map[K]V` 是哈希表，键必须可比较。切片、映射、函数不能作为键；包含这些字段的结构体也不能。零值是 `nil`，向 `nil` map 写入会 panic，读取则返回值类型的零值；因此声明后必须 `make` 或使用字面量初始化。

```go
package main

import "fmt"

func main() {
	scores := map[string]int{"alice": 90}
	scores["bob"] = 85

	if v, ok := scores["carol"]; ok {
		fmt.Println("carol:", v)
	} else {
		fmt.Println("carol 不存在")
	}

	delete(scores, "alice")
	for name, score := range scores {
		fmt.Println(name, score)
	}
	fmt.Println(len(scores))
}
```

comma-ok 用来区分「键不存在」与「值为零值」。`range` 遍历 map 的顺序是随机的，需要稳定顺序时把键取出来排序。并发读写 map 会直接触发运行时致命错误，必须加锁或使用 `sync.Map`（第 08 章）。

## 切片操作速查

- 截取 `s[low:high]`：左闭右开，容量从 `low` 到原容量末尾。
- 删除中间元素：`s = append(s[:i], s[i+1:]...)`。
- 过滤：在原切片上原地覆盖 `s[:0]`，注意这会修改底层数组。
- 判空：`len(s) == 0`，不要与 `nil` 比较来判断「有没有元素」。

`nil` 切片可以直接 `append`、`len`、`range`，行为与空切片一致；但 JSON 序列化时 `nil` 切片变成 `null`，空切片变成 `[]`，对外 API 要注意这个差异。

## 常见坑

- **以为切片传参是引用传递**：描述符按值复制，函数内 `append` 后长度变化不影响调用方。
- **保留大数组的小切片**：只要还有切片引用，整个底层数组都不会被回收，必要时复制出来。
- **对 nil map 赋值**：运行期 panic，先 `make`。
- **依赖 map 遍历顺序**：顺序随机，测试里尤其容易偶发失败。
- **在 range 中删除/新增 map 元素**：删除是安全的，新增行为不确定。
