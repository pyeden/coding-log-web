# 05 结构体、方法与接口

## 本章目标

理解结构体的字段导出规则，分清值接收者与指针接收者，掌握 Go 的隐式接口实现、类型断言与组合式设计。

## 结构体与字段导出

`struct` 把一组字段聚合为一个类型。字段名首字母大写表示**导出**（exported），包外可访问；小写仅包内可见。导出规则同样适用于函数、类型与方法，这是 Go 唯一的可见性机制。

结构体是值类型，赋值与传参都会复制。包含切片、映射、指针时复制的是描述符，底层数据仍共享。结构体字面量推荐写字段名，避免新增字段后位置错乱。

## 方法

方法就是带接收者的函数。接收者可以是值或指针：

- **值接收者**：方法内拿到副本，修改不影响原值；值类型与指针都能调用。
- **指针接收者**：方法内可修改原值；只有指针（或可寻址值）能调用。

选择原则：需要修改状态、结构体较大、或包含 `sync.Mutex` 等不可复制字段时用指针接收者；其余情况值接收者更安全。同一类型的方法集应保持一致，不要一半值一半指针。

```go
package main

import "fmt"

type Counter struct{ n int }

func (c *Counter) Inc()      { c.n++ }
func (c Counter) Value() int { return c.n }

func main() {
	var c Counter
	c.Inc()
	c.Inc()
	fmt.Println(c.Value())
}
```

`c.Inc()` 能对值调用指针方法，是因为编译器自动取地址（`(&c).Inc()`）；但把 `Counter` 放进接口时，只有 `*Counter` 才拥有 `Inc` 方法。

## 接口与隐式实现

接口定义方法集合，类型只要实现了全部方法就自动满足接口，**不需要显式声明**。这带来松耦合，也让「接口属于使用方」成为常见设计：先有小接口，再有实现。

```go
package main

import "fmt"

type Shape interface {
	Area() float64
}

type Rect struct {
	W, H float64
}

func (r Rect) Area() float64 { return r.W * r.H }

type Circle struct {
	R float64
}

func (c *Circle) Area() float64 { return 3.14159 * c.R * c.R }

func main() {
	shapes := []Shape{Rect{3, 4}, &Circle{2}}
	for _, s := range shapes {
		fmt.Printf("%.2f\n", s.Area())
	}
}
```

接口应保持小，一两个方法最常用；标准库的 `io.Reader`、`io.Writer`、`fmt.Stringer` 都是范本。空接口 `interface{}`（1.18+ 可写 `any`）不约束任何方法，任何类型都满足，但使用前通常需要类型断言，滥用会丢失静态类型检查。

方法集规则常被忽略：值类型 `T` 的方法集只包含值接收者方法，`*T` 才同时包含指针接收者方法。把 `T` 赋给接口时，如果接口方法由指针接收者实现，编译会直接失败。这是「同一类型的方法接收者应统一」的实际原因，而不只是风格问题。

## 类型断言与 type switch

```go
package main

import "fmt"

type Base struct{ ID int }

func (b Base) Describe() string { return fmt.Sprintf("base-%d", b.ID) }

type User struct {
	Base
	Name string
}

func describe(v interface{}) {
	switch x := v.(type) {
	case User:
		fmt.Println("user:", x.Name, x.Describe())
	case string:
		fmt.Println("string:", x)
	default:
		fmt.Printf("unknown: %T\n", x)
	}
}

func main() {
	u := User{Base: Base{ID: 7}, Name: "三木"}
	describe(u)
	describe("hello")
}
```

`v.(T)` 在失败时 panic，`v, ok := v.(T)` 才是安全写法。`type switch` 按顺序匹配具体类型，`case nil` 可判断接口是否为 nil。

## 组合优于继承

Go 没有继承，用**嵌入**（embedding）复用字段与方法：把 `Base` 匿名嵌入 `User`，`User` 就获得 `Base` 的字段与方法，且可被提升到外层。嵌入不是 is-a，而是 has-a 的语法糖；需要多态时用接口，需要复用实现时用组合。

## 常见坑

- **结构体含 `sync.Mutex` 却用值接收者**：复制锁会导致死锁或竞态。
- **接口值为 nil 但底层类型非 nil**：`var err error = (*MyError)(nil)` 的 `err != nil` 为真，判空要小心。
- **对接口做类型断言不做检查**：失败直接 panic。
- **为了「面向对象」堆继承层级**：Go 里优先小接口与组合。
- **导出字段没有文档注释**：`go doc` 生成的内容会很难读。
