# 09 异常、错误处理与契约

## 本章目标

理解异常（exception）的抛出、传播与栈展开过程，能写出基本异常安全的代码，并在异常与错误码之间做出合理选择。学完本章，你应该能解释 `noexcept` 对容器行为的影响，并知道为什么析构函数绝不能抛出异常。

## 核心概念

异常（exception）把错误从检测点传播到处理点；栈展开（stack unwinding）在传播过程中销毁自动对象；异常安全（exception safety）分为基本、强、不抛三级保证；`noexcept` 是编译期契约，违反即终止进程。

## 抛出与捕获

异常通过 `throw` 抛出，沿调用栈向上寻找匹配的 `catch`。匹配基于类型，允许派生类到基类的转换，因此自定义异常应继承 `std::exception` 或 `std::runtime_error`。捕获时**按 `const` 引用**（`catch (const MyError& e)`）：按值捕获会切片并可能再次抛出，按非 const 引用无法捕获临时对象。`catch (...)` 捕获所有异常，但拿不到信息，只适合在最外层做兜底与日志。

```cpp
#include <iostream>
#include <stdexcept>
#include <string>

class ParseError : public std::runtime_error {
public:
    explicit ParseError(const std::string& message) : std::runtime_error(message) {}
};

int parse_positive(int v) {
    if (v <= 0) { throw ParseError("value must be positive"); }
    return v;
}

int main() {
    try {
        parse_positive(-1);
    } catch (const ParseError& e) {
        std::cout << "caught: " << e.what() << '\n';
    } catch (const std::exception& e) {
        std::cout << "std: " << e.what() << '\n';
    }
}
```

## 栈展开与 RAII

异常抛出后，栈展开（stack unwinding）会依次销毁作用域内的自动对象，调用它们的析构函数。这正是 RAII 的价值：锁、文件、内存无需手写清理，异常路径与正常路径共用一套释放逻辑。若析构函数在展开过程中再次抛出异常，且未被捕获，程序会直接 `std::terminate`——所以析构函数必须 `noexcept`（C++11 起默认如此）。

```cpp
#include <iostream>
#include <utility>
#include <vector>

class Guard {
public:
    explicit Guard(int& flag) : flag_(flag) { flag_ = 1; }
    ~Guard() noexcept { flag_ = 0; }        // 析构不抛异常

    Guard(const Guard&) = delete;
    Guard& operator=(const Guard&) = delete;

private:
    int& flag_;
};

void append(std::vector<int>& dst, const std::vector<int>& src) {
    std::vector<int> copy = dst;            // 先复制：强异常安全
    copy.insert(copy.end(), src.begin(), src.end());
    dst.swap(copy);                          // swap 不抛，提交修改
}

int main() {
    int state = -1;
    {
        Guard g(state);
        std::cout << state << '\n';
    }
    std::cout << state << '\n';

    std::vector<int> a{1};
    append(a, {2, 3});
    std::cout << a.size() << '\n';
}
```

## 异常安全等级

业界通常分三档：

1. **基本保证（basic guarantee）**：异常后对象仍有效、可析构，但状态可能改变。
2. **强保证（strong guarantee）**：操作要么成功，要么对象保持原状（提交或回滚语义）。
3. **不抛保证（nothrow guarantee）**：承诺不抛异常，通常用于析构、`swap`、移动操作。

实现强保证的常用手法是 copy-and-swap：先在副本上完成可能失败的操作，再用不抛的 `swap` 提交。标准库容器的 `push_back` 一般提供强保证，前提是元素类型的移动构造不抛。

## noexcept

`noexcept` 是编译期契约：函数承诺不抛异常，违反时调用 `std::terminate`。它同时影响优化与泛型行为——`std::vector` 扩容时，只有在元素移动构造为 `noexcept` 时才使用移动，否则退回拷贝以维持强保证。因此移动构造、移动赋值、`swap` 都应标记 `noexcept`。

不要为了「性能」给可能失败的函数乱加 `noexcept`；一旦抛出就是进程终止，代价远大于收益。

## 异常 vs 错误码

异常的优点是错误无法被忽略、不污染返回值、可跨层传播；缺点是控制流不直观、某些环境（嵌入式、禁用 RTTI/异常的构建）不可用。错误码适合高频、可预期的失败（如解析用户输入、网络超时），但调用方容易忘记检查。

C++17 提供了 `std::optional` 表达「可能没有值」，`std::error_code` 表达系统错误；C++23 的 `std::expected<T, E>` 把「值或错误」放进同一个返回类型，兼顾显式检查与无异常构建（需 `<expected>`，C++23 起标准）。选择原则：**真正的异常状况用异常，可预期的失败用返回值类型**。

```cpp
#include <cstdlib>
#include <iostream>
#include <optional>
#include <system_error>

std::optional<int> to_int(const char* s) {
    if (s == nullptr) { return std::nullopt; }
    char* end = nullptr;
    long v = std::strtol(s, &end, 10);
    if (end == s || *end != '\0') { return std::nullopt; }
    return static_cast<int>(v);
}

int main() {
    if (auto v = to_int("42")) {
        std::cout << *v << '\n';
    }
    std::cout << (to_int("x") ? "ok" : "invalid") << '\n';

    std::error_code ec = std::make_error_code(std::errc::invalid_argument);
    std::cout << ec.message() << '\n';
}
```

## 常见坑 / 最佳实践

- 按 `const` 引用捕获，派生类异常放在基类之前。
- 析构函数不抛异常；需要清理失败时记录日志并吞掉。
- 构造函数抛出时，已构造的成员会按逆序析构，但对象本身不会——不要依赖构造函数体里的手工清理。
- 不要在 `catch` 中 `throw;` 之外重新抛出新类型而丢失原始信息，可用 `std::throw_with_nested`。
- 移动操作标记 `noexcept`，否则容器行为退化。
- 异常不用于普通控制流，也不要在热路径用异常做分支。
