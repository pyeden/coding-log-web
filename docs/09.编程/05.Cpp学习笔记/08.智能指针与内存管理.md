# 08 智能指针与内存管理

## 本章目标

用所有权（ownership）模型替代手工 `new` / `delete`，能正确选择 `unique_ptr`、`shared_ptr` 与 `weak_ptr`。学完本章，你应该能说明每个智能指针的代价，识别循环引用造成的泄漏，并为特殊资源编写自定义删除器。

## 核心概念

所有权（ownership）决定谁负责释放对象；`unique_ptr` 表达独占所有权，`shared_ptr` 通过控制块（control block）共享所有权；引用计数（reference count）归零时销毁对象；`weak_ptr` 观察但不拥有，用于打破循环引用。

## 裸指针的问题

裸指针（raw pointer）本身不表达所有权：函数收到 `T*` 时，无法从类型上判断它该不该 `delete`。由此产生三类缺陷：忘记释放（泄漏）、释放两次（double free）、释放后继续使用（悬空指针 / use-after-free）。此外，异常或提前 `return` 会跳过手写的 `delete`。现代 C++ 的原则是：**用类型表达所有权**，裸指针只用于「观察」，且优先用引用。

## unique_ptr：独占所有权

`std::unique_ptr<T>` 独占对象，不可拷贝、可移动，销毁时自动 `delete`。它的大小与裸指针相同（默认删除器为空类，可做空基类优化），没有运行时开销，应当作为默认选择。C++14 起用 `std::make_unique` 创建，避免 `new` 与构造顺序相关的异常泄漏。

```cpp
#include <cstdio>
#include <iostream>
#include <memory>

struct FileCloser {
    void operator()(std::FILE* f) const {
        if (f) { std::fclose(f); }
    }
};

int main() {
    auto p = std::make_unique<int>(42);
    std::cout << *p << '\n';

    std::unique_ptr<std::FILE, FileCloser> file(std::fopen("/dev/null", "r"));
    std::cout << (file ? "opened" : "failed") << '\n';

    auto arr = std::make_unique<int[]>(3);   // C++14 起支持数组
    arr[0] = 1;
    std::cout << arr[0] << '\n';
}
```

自定义删除器（custom deleter）让 `unique_ptr` 也能管理 `FILE*`、socket、库句柄。删除器是类型的一部分，因此不同删除器的 `unique_ptr` 是不同类型；需要放进同一容器时，用 `std::function` 包装或改用 `shared_ptr`。

## shared_ptr 与 weak_ptr

`std::shared_ptr<T>` 共享所有权，内部维护强引用计数（strong count）与控制块（control block），计数归零时销毁对象。拷贝 `shared_ptr` 会增加原子操作开销，因此不要无谓地按值传递；函数只观察对象时传 `const T&` 或 `T*`。

`std::weak_ptr<T>` 观察 `shared_ptr` 管理的对象但不增加强引用计数，用 `lock()` 获取临时 `shared_ptr`。它有两个用途：打破循环引用、实现缓存。

控制块的创建时机也值得注意：`shared_ptr<T>(new T)` 在控制块分配失败时仍会释放对象，但两次分配更容易产生碎片；`make_shared` 一次分配同时容纳对象与控制块，代价是只要还有 `weak_ptr`，整块内存都无法归还。

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <utility>

struct Node {
    std::string name;
    std::shared_ptr<Node> next;    // 强引用
    std::weak_ptr<Node> parent;    // 弱引用，打破循环

    explicit Node(std::string n) : name(std::move(n)) {}
};

int main() {
    auto a = std::make_shared<Node>("a");
    auto b = std::make_shared<Node>("b");
    a->next = b;
    b->parent = a;                 // 不增加 a 的引用计数

    std::cout << a.use_count() << ' ' << b.use_count() << '\n';
    if (auto p = b->parent.lock()) {
        std::cout << p->name << '\n';
    }
}
```

如果 `parent` 也写成 `shared_ptr`，`a` 与 `b` 会互相持有，计数永远不归零，形成循环引用泄漏——即使程序结束前没有崩溃，内存也不会释放。

## enable_shared_from_this

当对象内部需要把自己的 `shared_ptr` 交给外部（例如注册回调、加入容器）时，不能写 `shared_ptr<T>(this)`，那会创建第二个独立控制块，导致二次析构。正确做法是继承 `std::enable_shared_from_this<T>`，调用 `shared_from_this()`。前提是对象已经由 `shared_ptr` 管理，否则 C++17 起会抛 `std::bad_weak_ptr`。

```cpp
#include <iostream>
#include <memory>

class Session : public std::enable_shared_from_this<Session> {
public:
    std::shared_ptr<Session> self() { return shared_from_this(); }
    int id() const { return 7; }
};

int main() {
    auto s = std::make_shared<Session>();
    auto t = s->self();
    std::cout << t.use_count() << ' ' << t->id() << '\n';
}
```

## 对象生命周期与常见误区

- `std::make_shared` 一次分配同时容纳对象与控制块，比 `shared_ptr<T>(new T)` 少一次分配，也更异常安全。
- `shared_ptr` 的计数是原子的，但**对象本身不是线程安全的**；多线程读写同一对象仍需同步。
- 不要把 `shared_ptr` 当成「万能安全指针」：滥用共享所有权会让生命周期难以推理，默认仍应用 `unique_ptr`。
- 从 `unique_ptr` 转到 `shared_ptr` 可以隐式移动构造；反向不行。
- 释放顺序：`shared_ptr` 在最后一个持有者销毁时释放，若删除器捕获了其他对象，注意销毁顺序。
- `weak_ptr::lock()` 返回空表示对象已销毁，使用前必须检查。

## 常见坑 / 最佳实践

- 默认 `unique_ptr` + `make_unique`，只在真正共享所有权时用 `shared_ptr`。
- 不要用 `shared_ptr` 保存 `this`，用 `enable_shared_from_this`。
- 父子/双向关系用 `weak_ptr` 断开环。
- 函数参数表达「借用」时用 `T&` 或 `T*`，不要传 `shared_ptr` 增加计数。
- 数组用 `unique_ptr<T[]>` 或 `std::vector`，不要对 `shared_ptr` 用 `new T[n]`（C++17 没有数组版 `shared_ptr`，需自定义删除器）。
- 自定义删除器要可拷贝、不抛异常。
