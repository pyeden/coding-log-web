# 05 继承、多态与虚函数

## 本章目标

理解动态绑定（dynamic binding）的实现方式与代价，能正确使用 `virtual` / `override` / `final`，识别对象切片（object slicing）等常见错误。学完本章，你应该能判断什么时候该用继承、什么时候该用组合，并知道多继承与虚继承分别解决什么问题。

## 核心概念

继承（inheritance）建立 is-a 关系；虚函数（virtual function）通过虚表（vtable）实现运行时动态绑定；抽象类（abstract class）含纯虚函数，只定义接口；对象切片（object slicing）发生在按值传递派生类时，会丢失派生部分与动态类型。

## 继承与动态绑定

继承（inheritance）表达「is-a」关系。基类指针或引用指向派生类对象时，若成员函数是 `virtual`，调用会在运行时根据对象的动态类型分派，这就是多态（polymorphism）。实现上，含虚函数的类通常带一张虚函数表（vtable），每个对象含一个指向该表的指针（vptr）；调用虚函数是一次间接跳转，对象也会多出一个指针大小。因此「为所有函数加 virtual」既无必要也有成本。

三条纪律：

- 基类析构函数必须是 `virtual`，否则通过基类指针 `delete` 派生类对象是未定义行为。
- 派生类重写（override）时写 `override`，让编译器检查签名是否真的匹配。
- 不希望被继续继承或重写时写 `final`。

```cpp
#include <iostream>
#include <memory>
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual const char* name() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}
    double area() const override { return 3.141592653589793 * r_ * r_; }
    const char* name() const override { return "circle"; }

private:
    double r_;
};

class Rect : public Shape {
public:
    Rect(double w, double h) : w_(w), h_(h) {}
    double area() const override { return w_ * h_; }
    const char* name() const override { return "rect"; }

private:
    double w_, h_;
};

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(1.0));
    shapes.push_back(std::make_unique<Rect>(2.0, 3.0));
    for (const auto& s : shapes) {
        std::cout << s->name() << ' ' << s->area() << '\n';
    }
}
```

纯净虚函数（pure virtual）`= 0` 让类成为抽象类（abstract class），不能直接实例化，只能作为接口。抽象类可以有数据成员和已实现的成员函数，接口与实现并非互斥。

## 对象切片

把派生类对象**按值**赋给基类对象时，只会拷贝基类子对象，派生类部分被「切掉」，虚函数也不再分派到派生类。这就是对象切片（object slicing）。参数写成 `void f(Base b)` 是典型诱因；改成 `void f(const Base& b)` 即可保留多态。

```cpp
#include <iostream>

class Base {
public:
    virtual ~Base() = default;
    virtual const char* who() const { return "base"; }
};

class Derived : public Base {
public:
    const char* who() const override { return "derived"; }
};

void by_value(Base b) { std::cout << b.who() << '\n'; }        // 切片
void by_ref(const Base& b) { std::cout << b.who() << '\n'; }

int main() {
    Derived d;
    by_value(d);
    by_ref(d);
}
```

## dynamic_cast 与运行时类型识别

`dynamic_cast` 用于多态类型的安全向下转换：指针转换失败返回 `nullptr`，引用转换失败抛 `std::bad_cast`。它依赖 RTTI（run-time type information），有运行时开销，通常意味着设计上可以用虚函数替代。能用虚函数表达的行为，不要用 `dynamic_cast` 分支堆砌。

```cpp
#include <iostream>
#include <memory>

class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void hello() const { std::cout << "derived\n"; }
};

int main() {
    std::unique_ptr<Base> b = std::make_unique<Derived>();
    if (auto* d = dynamic_cast<Derived*>(b.get())) {
        d->hello();
    }

    Base plain;
    std::cout << (dynamic_cast<Derived*>(&plain) == nullptr) << '\n';
}
```

## 多继承与虚继承

C++ 允许多继承（multiple inheritance），常见用途是「一个实现 + 多个纯接口」。风险是菱形继承：两个中间类继承同一基类，最终类会含两份基类子对象，访问基类成员产生歧义。虚继承（virtual inheritance）让最终类只保留一份共享基类子对象，代价是布局更复杂、转换更慢。工程上更常见的做法是：接口用纯虚类，实现复用优先用组合（composition）。

## 组合优于继承

继承是编译期最紧的耦合：基类改动会影响所有派生类，且派生类暴露基类全部接口。组合（composition）通过成员对象复用实现，耦合更松、测试更容易。判断标准是「is-a」还是「has-a」：`Car` 有 `Engine`，应组合；`Circle` 是一种 `Shape`，才可以继承。默认选组合，只有在确实需要运行时多态接口时才用公有继承。

## 常见坑 / 最佳实践

- 基类析构必须 `virtual`，否则 `delete` 基类指针行为未定义。
- 重写一律写 `override`，避免「以为重写了其实隐藏了」。
- 不要按值传递多态基类，避免切片。
- 不要在构造/析构函数中调用虚函数，此时动态类型是当前类，不会分派到派生类。
- 多继承只用于接口组合，数据与实现复用优先组合。
- 用 `final` 关闭不必要的扩展点，帮助编译器去虚化（devirtualization）。
