# 04 类、对象与资源管理

## 本章目标

理解对象的构造与销毁顺序，能正确写出拷贝、移动语义，并用 RAII 把资源生命周期绑定到对象生命周期上。学完本章，你应该能判断一个类该遵循 Rule of Zero 还是 Rule of Five，并解释为什么「析构函数释放资源」是 C++ 最重要的设计习惯。

## 核心概念

构造函数（constructor）建立对象不变式，析构函数（destructor）释放资源；拷贝（copy）复制值语义，移动（move）转移资源所有权；特殊成员函数（special member functions）由编译器按规则生成或删除；RAII 把资源生命周期绑定到对象生命周期，是异常安全的基础。

## 类与成员初始化

类（class）默认私有，`struct` 默认公有，二者语义相同。构造函数用**成员初始化列表**（member initializer list）初始化成员，它比在函数体里赋值更高效，也是引用成员、`const` 成员和没有默认构造的成员唯一可行的初始化方式。成员按**声明顺序**初始化，与初始化列表书写顺序无关；顺序写错会产生 `-Wreorder` 警告。`explicit` 阻止单参构造函数的隐式转换，除非你确实需要 `std::string s = "x";` 这类转换，否则默认加上。

## 析构、拷贝与移动

析构函数（destructor）在对象生命周期结束时自动调用，是释放内存、关闭文件、解锁互斥量的地方。编译器会自动生成拷贝构造、拷贝赋值、移动构造、移动赋值与析构，规则是：

- 只管理「值」的类（成员都是 `std::string`、`std::vector` 等 RAII 类型）→ **Rule of Zero**：一个都不写。
- 自己管理裸资源（`new`、文件描述符）→ **Rule of Five**：五个特殊成员函数全部显式定义或 `= delete`。
- 只写析构不写拷贝 → 编译器仍生成拷贝，导致 double free，这是历史遗留的经典陷阱。

C++11 起，移动构造（move constructor）通过「窃取」源对象资源来避免深拷贝，参数是 `T&&`，应标记 `noexcept`，否则 `std::vector` 扩容时不会使用移动。

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>

class Logger {
public:
    explicit Logger(std::string tag) : tag_(std::move(tag)) {
        std::cout << "open " << tag_ << '\n';
    }
    ~Logger() { std::cout << "close " << tag_ << '\n'; }

    Logger(const Logger&) = delete;             // 不允许复制句柄
    Logger& operator=(const Logger&) = delete;

private:
    std::string tag_;
};

int main() {
    Logger log("demo");
    std::vector<int> xs{1, 2, 3};   // 自身遵循 Rule of Zero
    std::cout << xs.size() << '\n';
}
```

## Rule of Five 的完整写法

自己管理动态数组时，必须同时处理拷贝、移动与析构。下面用 copy-and-swap 实现拷贝赋值，天然具备强异常安全；移动构造把指针置空，避免析构时重复释放：

```cpp
#include <cstddef>
#include <iostream>
#include <utility>

class Buffer {
public:
    explicit Buffer(std::size_t n) : data_(new int[n]()), size_(n) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& other)
        : data_(new int[other.size_]), size_(other.size_) {
        for (std::size_t i = 0; i < size_; ++i) data_[i] = other.data_[i];
    }

    Buffer& operator=(const Buffer& other) {
        Buffer tmp(other);
        swap(tmp);
        return *this;
    }

    Buffer(Buffer&& other) noexcept : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;
        other.size_ = 0;
    }

    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            Buffer tmp(std::move(other));
            swap(tmp);
        }
        return *this;
    }

    void swap(Buffer& other) noexcept {
        std::swap(data_, other.data_);
        std::swap(size_, other.size_);
    }

    std::size_t size() const { return size_; }

private:
    int* data_;
    std::size_t size_;
};

int main() {
    Buffer a(4);
    Buffer b = a;
    Buffer c = std::move(b);
    std::cout << a.size() << ' ' << c.size() << '\n';
}
```

## 运算符重载、friend 与 static 成员

运算符重载让自定义类型拥有与内置类型一致的表达方式，但不要滥用：`+` 应当表示加法而不是「打印」。成员函数形式的重载隐含 `this` 作为左操作数；需要左操作数为非类类型（如 `std::ostream`）时，用非成员函数并在需要访问私有成员时声明 `friend`。`static` 成员属于类而非对象，需要在类外定义（C++17 可用 `inline static` 在类内定义）。

```cpp
#include <iostream>

class Vec2 {
public:
    Vec2(double x, double y) : x_(x), y_(y) {
        ++count_;
    }

    Vec2 operator+(const Vec2& rhs) const {
        return Vec2(x_ + rhs.x_, y_ + rhs.y_);
    }

    double dot(const Vec2& rhs) const { return x_ * rhs.x_ + y_ * rhs.y_; }

    friend std::ostream& operator<<(std::ostream& os, const Vec2& v);

    static int created() { return count_; }

private:
    double x_, y_;
    static int count_;
};

int Vec2::count_ = 0;

std::ostream& operator<<(std::ostream& os, const Vec2& v) {
    return os << '(' << v.x_ << ", " << v.y_ << ')';
}

int main() {
    Vec2 a(1, 2);
    Vec2 b(3, 4);
    std::cout << (a + b) << ' ' << a.dot(b) << ' ' << Vec2::created() << '\n';
}
```

## RAII：资源获取即初始化

RAII（Resource Acquisition Is Initialization）指在构造函数中获取资源、在析构函数中释放资源，把「配对操作」交给编译器保证。它是异常安全的基础：栈展开（stack unwinding）时析构函数一定会执行。标准库的 `std::vector`、`std::string`、`std::fstream`、`std::lock_guard` 都是 RAII 类型。自己写 RAII 类时，记得禁用拷贝或实现引用计数，避免资源被释放两次。

## 常见坑 / 最佳实践

- 优先 Rule of Zero，把资源交给标准库类型管理。
- 写了析构函数就检查拷贝/移动是否需要禁用或实现。
- 移动构造与移动赋值标记 `noexcept`，否则容器不会采用。
- 单参构造函数加 `explicit`，除非需要隐式转换。
- 初始化列表顺序与成员声明顺序保持一致。
- 析构函数不要抛异常；派生类析构自动调用基类析构，基类析构需为 `virtual`（见下一章）。
