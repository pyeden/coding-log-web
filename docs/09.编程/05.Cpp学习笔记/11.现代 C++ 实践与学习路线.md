# 11 现代 C++ 实践与学习路线

## 本章目标

把前面十章的知识串成一条演进线索：C++11 到 C++23 各自解决了什么问题，工程上该用什么工具链与规范。学完本章，你应该能为一个新项目选定标准版本、搭好构建与依赖管理，并规划后续学习路径。

## 核心概念

标准版本（C++11/14/17/20/23）决定可用特性集合；编译期计算（compile-time computation）把工作前移到构建阶段；工具链（toolchain）涵盖编译器、构建系统、依赖管理与检查器；代码规范（coding guidelines）把社区经验固化为可执行规则。

## 标准演进

C++ 每三年发布一版，语言与标准库同步演进：

- **C++11**：现代 C++ 的起点。`auto`、范围 for、lambda、右值引用与移动语义、`nullptr`、`enum class`、`std::thread`、`std::unique_ptr`。
- **C++14**：泛型 lambda、返回类型推导、`std::make_unique`、变量模板。
- **C++17**：结构化绑定、`if constexpr`、折叠表达式、`std::optional` / `variant` / `any`、`std::string_view`、`std::filesystem`、并行算法。**本书教学基准**。
- **C++20**：concepts、ranges、协程（coroutines）、modules、`std::span`、`std::format`、`std::jthread`、三路比较 `<=>`。
- **C++23**：`std::expected`、`std::print`、`std::flat_map`、`std::mdspan`、`import std;` 的标准化推进。

标准版本不是越新越好：要看编译器、平台与团队能力。教学与面试以 C++17 为共同基线最稳妥；新项目在工具链允许时可以上 C++20。

## 编译期计算

现代 C++ 的一大趋势是把工作从运行期移到编译期：`constexpr` 函数、`constexpr` 变量、`static_assert`、模板元编程，以及 C++20 的 `consteval` / `constinit`。好处是零运行时开销、错误提前暴露；代价是编译时间与报错可读性。

```cpp
#include <array>
#include <iostream>

constexpr int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) { result *= i; }
    return result;
}

int main() {
    constexpr std::array<int, 5> table{factorial(0), factorial(1), factorial(2),
                                       factorial(3), factorial(4)};
    static_assert(table[4] == 24, "阶乘表错误");
    std::cout << table[3] << '\n';
}
```

C++20 的 `consteval` 强制函数只能在编译期求值，`constinit` 保证变量在静态初始化阶段完成初始化，避免静态初始化顺序问题。

## 现代写法示例

把结构化绑定、`if` 初始化语句、`optional` 与 `filesystem` 组合起来，代码会比 C++98 风格短很多，且异常安全：

```cpp
#include <filesystem>
#include <iostream>
#include <map>
#include <optional>
#include <string>

std::optional<int> find_id(const std::map<std::string, int>& m,
                           const std::string& key) {
    auto it = m.find(key);
    if (it == m.end()) { return std::nullopt; }
    return it->second;
}

int main() {
    std::map<std::string, int> ids{{"cpp", 17}};
    if (auto id = find_id(ids, "cpp"); id) {      // C++17 if 初始化语句
        std::cout << *id << '\n';
    }

    auto [key, value] = *ids.begin();             // C++17 结构化绑定
    std::cout << key << ' ' << value << '\n';

    std::filesystem::path p = "/tmp/demo.txt";
    std::cout << p.filename().string() << ' '
              << p.extension().string() << '\n';
}
```

## 工具链与依赖管理

- **构建**：CMake 是事实标准，配合 `CMakePresets.json` 固化配置。不要在项目里提交 `build/`。
- **依赖**：Conan 或 vcpkg 管理第三方库；小项目也可以直接用 `FetchContent`。
- **格式化**：`clang-format` 统一风格，提交前自动运行。
- **静态检查**：`clang-tidy` 能发现大量现代 C++ 反模式；配合 CI 使用。
- **动态检查**：AddressSanitizer、UndefinedBehaviorSanitizer、ThreadSanitizer 分别抓内存、UB 与数据竞争。
- **编译器矩阵**：至少覆盖 Clang 与 GCC，有条件再加 MSVC；不同标准库实现的诊断差异很大。

## 代码规范

C++ Core Guidelines（isocpp.org 维护）是社区共识度最高的规范集合，重点包括：用 RAII 管理资源、避免裸 `new` / `delete`、优先 `const` 与不变式、按值/引用传递的规则、避免隐式转换、用 `gsl::span` 之类的视图类型（C++20 后用 `std::span`）。团队规范应在此基础上做减法，而不是另起一套。

## 学习路线

1. **语言基础**（第 1–3 章）：编译模型、类型、控制流、函数。
2. **对象与资源**（第 4–5 章）：类、RAII、继承与多态。此时应能读懂标准库容器的接口。
3. **泛型与标准库**（第 6–7 章）：模板、容器、算法。开始刷算法题与阅读 libstdc++ 实现。
4. **内存与错误处理**（第 8–9 章）：智能指针、异常安全。
5. **并发**（第 10 章）：线程、锁、原子操作。配合 ThreadSanitizer 做实验。
6. **工程化**（第 11 章）：CMake、依赖管理、CI、代码规范。
7. **深入方向**：性能优化与缓存友好、无锁数据结构、编译期编程、C++20 modules 与协程、领域库（图形、网络、量化）。

建议的练习方式：每个主题写一个不超过 200 行的小项目（如 JSON 解析器、线程池、简易容器），并用 sanitizer 与单元测试验证。只读不写很难真正掌握 C++ 的对象生命周期与边界条件。

## 常见坑 / 最佳实践

- 新项目先固定标准版本与编译器矩阵，再写代码。
- 依赖尽量少，能用标准库就不引入第三方。
- CI 必须跑构建、测试、format 与 sanitizer，缺一不可。
- 不要追新特性而牺牲可读性；团队不熟悉的特性先做小范围验证。
- 阅读标准文档时以 cppreference 查用法、以 eel.is 草案查精确语义。
- 长期维护的项目要建立「禁止清单」：禁止裸 `new`、禁止 `using namespace std;`、禁止在头文件定义非 inline 函数等。
