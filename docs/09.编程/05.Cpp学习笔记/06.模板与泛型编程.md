# 06 模板与泛型编程

## 本章目标

理解模板（template）的实例化机制，能写函数模板、类模板与可变参数模板，并掌握 C++17 可用的约束手段。学完本章，你应该能解释「模板为什么必须放头文件」，并知道 SFINAE 解决什么问题、C++20 concepts 又如何把它变得可读。

## 核心概念

模板（template）是编译期生成代码的配方；实例化（instantiation）在用具体类型替换参数后发生；特化（specialization）为特定类型提供专门实现，偏特化只适用于类模板；SFINAE 让不匹配的候选静默退出重载集，是 C++17 约束模板的主要手段。

## 函数模板与推导

函数模板不是函数，而是生成函数的「配方」。调用时编译器根据实参推导模板参数，实例化（instantiate）出具体函数。推导会丢弃顶层 `const`、把数组退化为指针、把函数退化为函数指针；需要保留时用引用参数。两个参数类型不同时，`max_of(1, 2.0)` 会推导失败，因为 `T` 无法同时是 `int` 和 `double`——这是模板报错冗长的常见原因。

```cpp
#include <iostream>
#include <string>

template <typename T>
T max_of(T a, T b) {
    return a < b ? b : a;
}

template <typename T>
class Box {
public:
    explicit Box(T v) : value_(v) {}
    T get() const { return value_; }

private:
    T value_;
};

template <typename T>
class Box<T*> {                 // 偏特化：针对指针
public:
    explicit Box(T* p) : p_(p) {}
    T* get() const { return p_; }

private:
    T* p_;
};

int main() {
    Box<int> a(1);
    int x = 2;
    Box<int*> b(&x);
    std::cout << max_of(3, 7) << ' ' << a.get() << ' ' << *b.get() << '\n';
}
```

类模板可以全特化（`template <> class Box<char>`）或偏特化（部分参数固定、或针对指针/引用形态）。函数模板只支持全特化，不支持偏特化；需要「按条件选择实现」时通常改用重载或 `if constexpr`。

模板参数也可以带默认值，例如 `template <typename T, typename Alloc = std::allocator<T>> class MyVector;`，这样使用者只需写出元素类型。默认参数同样遵循「从右向左连续」的规则。

## 可变参数模板与折叠表达式

可变参数模板（variadic template）用 `typename... Args` 接收任意个类型，用 `args...` 展开。C++17 引入折叠表达式（fold expression），把二元运算符应用到整个参数包上：`(args + ...)` 是右折叠，`(... + args)` 是左折叠。它让「求和」「依次打印」这类操作不再需要递归终止函数。

```cpp
#include <iostream>
#include <string>

template <typename... Args>
auto sum(Args... args) {
    return (args + ...);        // C++17 折叠表达式
}

template <typename... Args>
void print_all(const Args&... args) {
    ((std::cout << args << ' '), ...);
    std::cout << '\n';
}

int main() {
    std::cout << sum(1, 2, 3, 4) << '\n';
    print_all(1, std::string("two"), 3.0);
}
```

注意 `sum()` 空参数包时 `(args + ...)` 无法确定初值，需要写成 `(args + ... + 0)` 提供空包值。

## SFINAE 与 enable_if

SFINAE（Substitution Failure Is Not An Error）指模板参数替换失败时，该候选从重载集中移除而不是报错。经典用法是用 `std::enable_if` 根据类型特征约束重载：整型版本与浮点版本各自只在条件成立时存在。C++17 提供 `std::enable_if_t` 与 `_v` 变量模板，写法比 C++11 简洁很多。

```cpp
#include <iostream>
#include <type_traits>

template <typename T>
std::enable_if_t<std::is_integral_v<T>, T> twice(T v) {
    return static_cast<T>(v * 2);
}

template <typename T>
std::enable_if_t<std::is_floating_point_v<T>, T> twice(T v) {
    return v * 2;
}

int main() {
    std::cout << twice(3) << ' ' << twice(1.5) << '\n';
}
```

SFINAE 的问题是错误信息难读、约束意图藏在返回类型里。C++20 的 concepts 与 `requires` 把约束提到语法前台，可以直接写 `template <std::integral T>`，并在不满足时给出清晰的诊断。这是 C++20 特性，C++17 项目仍应使用 `enable_if` 或 `if constexpr`。

## 模板与头文件

模板定义必须对使用点可见，因此通常全部写在头文件里。若把定义放 `.cpp`，编译器在使用它的翻译单元里看不到函数体，只能在链接期报未定义符号。需要缩短编译时间时，可以用显式实例化（explicit instantiation）把常用类型固定在某个 `.cpp` 中：

```cpp
// 头文件中：定义必须对使用点可见
template <typename T>
T clamp_value(T v, T lo, T hi) {
    return v < lo ? lo : (hi < v ? hi : v);
}

// 某个 .cpp 中显式实例化，固定常用类型
template int clamp_value<int>(int, int, int);
```

代价是该模板不再支持任意类型。多数业务代码不必这么做，优先保证正确性与可维护性。

## 常见坑 / 最佳实践

- 模板定义放头文件；确需隐藏实现时用显式实例化。
- 模板报错要从「第一个错误」读起，后面的错误往往是连锁反应。
- 约束尽量写清楚：C++17 用 `enable_if` / `if constexpr`，C++20 用 concepts。
- 不要在模板里假设类型可拷贝；需要时用 `std::is_copy_constructible_v` 检查或改用引用。
- 类型推导失败时显式指定模板参数，如 `max_of<double>(1, 2.5)`。
- 模板代码同样要写单元测试，且覆盖多个实例化类型。
