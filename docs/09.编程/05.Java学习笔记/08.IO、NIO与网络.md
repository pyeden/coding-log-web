# 08 IO、NIO与网络

## 本章目标

分清「流式 IO」与「NIO.2 文件 API」的适用场景，掌握字符集与缓冲的正确姿势，能用 `HttpClient` 发一个带超时的 HTTP 请求，并知道阻塞与非阻塞在网络编程中的取舍。

## 核心概念

`java.io` 是**流**（stream）模型：`InputStream`/`OutputStream` 处理字节，`Reader`/`Writer` 处理字符，方向单一、阻塞读写。`java.nio` 引入**缓冲区**（`ByteBuffer`）与**通道**（`Channel`），支持非阻塞与多路复用（`Selector`），是 Netty 等框架的基础。

日常文件操作首选 `java.nio.file`（NIO.2，Java 7）：`Path` 表示路径、`Files` 提供静态工具方法。`Files.readString`/`writeString`（Java 11）、`Files.readAllLines`、`Files.lines`（返回惰性 `Stream`）、`Files.walk`（遍历目录树）、`Files.copy`/`move` 覆盖了绝大多数需求，比手写流简单且不易泄漏。

字符集是乱码的唯一根源。Java 18 起（JEP 400）`file.encoding` 默认 UTF-8，但**读写文件时仍应显式指定** `StandardCharsets.UTF_8`，因为默认值会随 JVM 参数变化。字节与字符之间必须经过 `Charset` 转换，绝不能用 `new String(bytes)` 这种依赖平台默认编码的写法。

缓冲的意义在于减少系统调用：`BufferedReader`/`BufferedWriter` 把多次小读写合并。`Files.newBufferedReader` 已内置缓冲，无需再包一层。

网络方面，`java.net.Socket` 是阻塞式 TCP；JDK 11 引入的 `java.net.http.HttpClient` 支持 HTTP/2、连接池与异步，是替代 `HttpURLConnection` 的官方方案。任何网络调用都必须设置**连接超时**与**请求超时**，否则故障时会长时间挂起。

阻塞与非阻塞的选择取决于并发模型：一个连接一个线程时，阻塞 IO 配合虚拟线程已经足够；需要单线程管理上万连接时，才需要 `Selector` 与非阻塞通道。不要为了「高级」提前引入 Reactor 模型，复杂度会成倍上升。

`ByteBuffer` 有三个状态量：position（读写位置）、limit（读写边界）、capacity（容量）。写完后 `flip()` 把 limit 设为 position、position 归零，才能开始读；读完用 `clear()` 或 `compact()` 复位。顺序写错是 NIO 最常见的 bug。

文件操作还要关注原子性：同文件系统内 `Files.move(src, dst, StandardCopyOption.ATOMIC_MOVE)` 是原子的，适合「写临时文件再替换」的发布模式，避免读方看到半截内容。

缓冲区大小不是越大越好，8KB 到 64KB 通常已经足够，过大只会增加内存占用与首次延迟。字符集方面，`CharsetDecoder` 可以配置遇到非法字节时的行为（`REPORT`、`REPLACE`、`IGNORE`），解析外部数据时不要默认忽略错误。网络编程还要区分连接超时与读取超时：前者管 TCP 握手，后者管对端迟迟不返回数据。

## 代码示例

文件读写：显式字符集 + try-with-resources：

```java
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;

public class FileDemo {
    public static void main(String[] args) throws IOException {
        Path dir = Files.createTempDirectory("java-note");
        Path file = dir.resolve("notes.txt");

        Files.writeString(file, "第一行\n第二行\n", StandardCharsets.UTF_8);
        List<String> lines = Files.readAllLines(file, StandardCharsets.UTF_8);
        System.out.println(lines);

        Files.writeString(file, "追加一行\n", StandardCharsets.UTF_8,
                java.nio.file.StandardOpenOption.APPEND);
        try (var reader = Files.newBufferedReader(file, StandardCharsets.UTF_8)) {
            reader.lines().forEach(line -> System.out.println("> " + line));
        }

        System.out.println("大小 = " + Files.size(file) + " 字节");
        Files.deleteIfExists(file);
        Files.deleteIfExists(dir);
    }
}
```

目录遍历用 `Files.walk`，它是惰性流，必须关闭：

```java
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;
import java.util.stream.Stream;

public class WalkDemo {
    static long totalSize(Path root) throws IOException {
        try (Stream<Path> paths = Files.walk(root)) {
            return paths.filter(Files::isRegularFile)
                    .mapToLong(p -> {
                        try {
                            return Files.size(p);
                        } catch (IOException e) {
                            return 0L;
                        }
                    })
                    .sum();
        }
    }

    public static void main(String[] args) throws IOException {
        Path root = Files.createTempDirectory("walk");
        Files.writeString(root.resolve("a.txt"), "abc");
        Files.createDirectories(root.resolve("sub"));
        Files.writeString(root.resolve("sub/b.txt"), "defg");
        System.out.println("总字节 = " + totalSize(root));
        try (Stream<Path> paths = Files.walk(root)) {
            System.out.println(paths.toList().size() + " 个条目");
        }
    }
}
```

`Files.walk` 返回的流持有打开的目录句柄，忘记关闭在长跑服务里会句柄泄漏。

`HttpClient` 发起带超时的 GET 请求：

```java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;

public class HttpDemo {
    public static void main(String[] args) throws Exception {
        HttpClient client = HttpClient.newBuilder()
                .connectTimeout(Duration.ofSeconds(3))
                .followRedirects(HttpClient.Redirect.NORMAL)
                .build();

        HttpRequest request = HttpRequest.newBuilder(URI.create("https://dev.java/learn/"))
                .timeout(Duration.ofSeconds(5))
                .header("Accept", "text/html")
                .GET()
                .build();

        HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());
        System.out.println("status = " + response.statusCode());
        System.out.println("bytes = " + response.body().length());
    }
}
```

异步版本用 `sendAsync` 返回 `CompletableFuture<HttpResponse<T>>`，可配合第 07 章的编排手法串联多个请求。

## 常见坑

- **不关流**：文件句柄泄漏，Windows 上还会导致文件无法删除。一律 try-with-resources。
- **`FileReader` 不指定字符集**：依赖平台默认编码，跨机器乱码。用 `Files.newBufferedReader(path, UTF_8)`。
- **逐字节 `read()` 循环**：每次一个系统调用，性能极差，必须加缓冲。
- **`Files.lines`/`walk` 忘记关闭**：返回的是流，底层持有资源。
- **网络请求不设超时**：默认可能无限等待，必须显式配置连接与请求超时。
- **把 `ByteBuffer` 的 `flip()` 忘了**：写完直接读会读到位置 0 之后，得到空数据。
