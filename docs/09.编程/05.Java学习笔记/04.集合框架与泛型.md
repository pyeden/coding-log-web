# 04 集合框架与泛型

## 本章目标

把「什么时候用 `List`、什么时候用 `Set`、什么时候用 `Map`」变成条件反射，理解 `ArrayList` 与 `HashMap` 的复杂度边界，并能正确书写带通配符的泛型签名。目标是避免把 `O(n)` 操作写进循环。

## 核心概念

Java 集合框架（Collections Framework）分两条线：`Collection`（单个元素的容器）与 `Map`（键值对）。`Collection` 下三大接口是 `List`（有序、可重复）、`Set`（不可重复）、`Queue`/`Deque`（队列与双端队列）。

选型从复杂度出发：`ArrayList` 随机访问 `O(1)`、尾部追加均摊 `O(1)`、中间插入 `O(n)`；`LinkedList` 头尾操作 `O(1)` 但随机访问 `O(n)`，实践中它很少是最优选择，`ArrayDeque` 更适合当队列。`HashSet`/`HashMap` 的查找、插入均摊 `O(1)`，代价是元素无序且依赖 `hashCode` 质量；需要排序时用 `TreeMap`/`TreeSet`，操作 `O(log n)`。

`HashMap` 的内部是数组 + 链表 + 红黑树：哈希冲突时同桶元素挂成链表，链表长度超过阈值（8）且容量不小于 64 时转为红黑树，退化为 `O(log n)`。所以**容量与负载因子**（load factor，默认 0.75）会影响性能，预知元素规模时用 `new HashMap<>(expected / 0.75f + 1)` 可减少扩容。

遍历时修改集合会触发 `ConcurrentModificationException`（fail-fast）。要么用 `Iterator.remove()`，要么用 `removeIf`，要么改用 `ConcurrentHashMap`。

`SequencedCollection`（Java 21 正式）给 `List`/`Deque` 等加上统一的 `getFirst`/`getLast`/`reversed`，此前只能靠 `list.get(0)` 或 `list.get(list.size() - 1)`。

**泛型**（generics）在编译期提供类型安全，运行期被**类型擦除**（type erasure）：`List<String>` 与 `List<Integer>` 在运行时是同一个类，因此不能 `new T[]`、不能对泛型做 `instanceof`、静态成员不能使用类的类型参数。擦除的补偿是编译器在取值处插入强制转换。

通配符遵循 **PECS** 原则：Producer `extends`，Consumer `super`。只读取用 `? extends T`，只写入用 `? super T`，既读又写就用确定的 `T`。

`for`-each 只是迭代器的语法糖，编译器会展开成 `iterator()`、`hasNext()`、`next()` 三步。因此自定义容器只要实现 `Iterable`，就能被增强 `for` 与 Stream 直接使用。

比较器（`Comparator`）的契约常被忽视：`compare` 必须满足自反、反对称与传递性，否则 `TimSort` 会抛 `IllegalArgumentException: Comparison method violates its general contract!`。用 `Comparator.comparing(...).thenComparing(...)` 组合，比手写 `if` 链更不容易出错。

容量与内存也值得关注：`ArrayList` 默认容量 10，扩容为 1.5 倍；`HashMap` 默认 16，扩容翻倍并重哈希。批量插入前用 `ensureCapacity` 或预设初始容量，可避免多次数组复制，十万级数据时差别明显。

并发读写时不要用 `Collections.synchronizedMap` 包一层就混用复合操作：先检查再写入依然需要外部加锁，直接用 `ConcurrentHashMap` 的 `putIfAbsent`、`computeIfAbsent` 更安全。另外 `Map.of` 最多支持 10 组键值对，超出要用 `Map.ofEntries`，它返回不可变实例，任何修改都会抛异常，适合当常量表。

## 代码示例

常用集合操作与 Java 21 的顺序集合接口：

```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class CollectionBasics {
    public static void main(String[] args) {
        List<String> langs = new ArrayList<>(List.of("Java", "Kotlin", "Go"));
        langs.add("Rust");
        System.out.println(langs.getFirst());        // Java（Java 21）
        System.out.println(langs.getLast());         // Rust
        System.out.println(langs.reversed());        // 视图，不复制

        Map<String, Integer> counts = new HashMap<>();
        for (String lang : langs) {
            counts.merge(lang, 1, Integer::sum);
        }
        counts.forEach((k, v) -> System.out.println(k + " -> " + v));

        langs.removeIf(s -> s.startsWith("K"));
        System.out.println(langs);
    }
}
```

`merge`、`computeIfAbsent`、`getOrDefault` 是 `Map` 的三个高频方法，能省掉大量 `if (map.get(k) == null)` 分支。

带边界的泛型类与 PECS 方法：

```java
import java.util.ArrayList;
import java.util.Collection;
import java.util.List;

public class Box<T extends Comparable<T>> {
    private final List<T> items = new ArrayList<>();

    public void add(T item) {
        items.add(item);
    }

    public T max() {
        T best = null;
        for (T item : items) {
            if (best == null || item.compareTo(best) > 0) {
                best = item;
            }
        }
        return best;
    }

    // 生产者用 extends：只读，可接收 List<Integer> 传给 Collection<Number>
    static double sum(Collection<? extends Number> numbers) {
        double total = 0;
        for (Number n : numbers) {
            total += n.doubleValue();
        }
        return total;
    }

    // 消费者用 super：只写
    static void fill(List<? super Integer> target, int n) {
        for (int i = 1; i <= n; i++) {
            target.add(i);
        }
    }

    public static void main(String[] args) {
        Box<String> box = new Box<>();
        box.add("b");
        box.add("a");
        System.out.println(box.max());
        System.out.println(sum(List.of(1, 2.5, 3)));
        List<Number> sink = new ArrayList<>();
        fill(sink, 3);
        System.out.println(sink);
    }
}
```

擦除带来的限制与不可变视图：

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class ErasureDemo {
    // 泛型方法：类型参数只存在于编译期
    static <E> List<E> single(E element) {
        List<E> list = new ArrayList<>();
        list.add(element);
        return list;
    }

    public static void main(String[] args) {
        List<String> names = single("java");
        List<Integer> nums = single(21);
        System.out.println(names.getClass() == nums.getClass());   // true：都是 ArrayList

        List<String> readOnly = Collections.unmodifiableList(names);
        try {
            readOnly.add("kotlin");
        } catch (UnsupportedOperationException e) {
            System.out.println("视图不可修改");
        }
    }
}
```

需要真正的不可变副本时用 `List.copyOf`（Java 10），它复制一份并对 `null` 元素报错。

## 常见坑

- **在 `for` 循环里 `list.contains`**：`ArrayList` 的 `contains` 是 `O(n)`，嵌套后变 `O(n²)`，应换 `HashSet`。
- **`Arrays.asList` 返回定长列表**：`add`/`remove` 抛 `UnsupportedOperationException`，需要可变时包一层 `new ArrayList<>(...)`。
- **`List.of` 不接受 `null`**：传 `null` 直接 NPE，迁移老代码时容易踩。
- **可变对象作 `HashMap` 的键**：键被修改后哈希值变化，原条目再也找不到。
- **`subList` 是视图**：对原列表的结构性修改会让子列表失效。
- **滥用 `LinkedList`**：除频繁头插外，绝大多数场景 `ArrayList` 更快（缓存友好）。
