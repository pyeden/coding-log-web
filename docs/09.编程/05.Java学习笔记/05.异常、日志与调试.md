# 05 异常、日志与调试

## 本章目标

分清受检异常与运行时异常的适用场景，用 try-with-resources 正确释放资源，用 JDK 自带的 `System.Logger` 打出可检索的日志，并在不看 IDE 的情况下定位线上问题。

## 核心概念

Throwable 体系分两支：`Error`（JVM 级严重问题，如 `OutOfMemoryError`，业务代码不应捕获）与 `Exception`。`Exception` 下又分**受检异常**（checked exception，继承 `Exception` 但不继承 `RuntimeException`，编译器强制处理）与**非受检异常**（unchecked，继承 `RuntimeException`）。

判断标准不是「严不严」，而是「调用方能否合理地做补救」。文件不存在、网络超时这类可恢复情形适合受检异常；参数非法、状态错误、编程 bug 属于非受检异常，让程序尽早失败。

`try`-with-resources（Java 7）自动调用 `AutoCloseable.close()`，且关闭顺序与声明顺序相反。若 `try` 块与 `close()` 都抛异常，后者作为**抑制异常**（suppressed）挂在主异常上，可用 `getSuppressed()` 查看，不再静默丢失。

`multi-catch` 用 `|` 合并处理逻辑相同的分支，但捕获的变量隐式为 `final`。`finally` 一定会执行（`System.exit` 除外），因此不要在 `finally` 里 `return`，它会吞掉异常。

日志遵循「级别即语义」：`ERROR` 表示需要人介入，`WARN` 表示可自愈的异常，`INFO` 记录关键状态变迁，`DEBUG`/`TRACE` 只在排查时开启。日志内容要包含**可检索的上下文**（ID、关键参数），不要只写「失败了」。`System.Logger`（Java 9）是 JDK 内置门面，可对接 SLF4J 等实现。

调试三板斧：读**栈轨迹**（stack trace）从最内层 `Caused by` 看起；用 `jps` 找进程、`jstack` 抓线程栈、`jcmd` 看堆与 GC；交互式用 `jdb` 或 IDE 断点。

异常设计有一条主线：**异常也是 API**。自定义异常应继承合适的父类并提供稳定类型，而不是让调用方解析消息文本判断错误。业务异常与系统异常要分开：前者可展示给用户，后者必须记录完整栈并触发告警。

日志有两条硬规则：不输出密码、令牌、完整证件号等敏感信息；不把大对象 `toString()` 直接打进日志，既慢又可能触发懒加载异常。参数化日志在级别未开启时不做字符串拼接，这正是它的性能优势来源。

`jcmd` 之外，JDK 还自带 JFR（Java Flight Recorder）。用 `jcmd <pid> JFR.start duration=60s filename=rec.jfr` 可在生产低开销采样，再用 `jfr print` 或 JDK Mission Control 分析，比事后猜测可靠得多。

线上排障还需要一个贯穿全链路的追踪 ID（trace id）：在入口生成、写入日志上下文，否则多线程日志交错后无法还原一次请求的完整路径。另外注意 `finally` 里的异常覆盖问题——`try` 抛出异常、`finally` 又抛一个，后者会吞掉前者，资源释放应交给 try-with-resources 而不是手写 `finally`。

## 代码示例

资源释放交给 try-with-resources，自定义资源实现 `AutoCloseable`：

```java
public class ResourceDemo {
    static class Connection implements AutoCloseable {
        private final String name;

        Connection(String name) {
            this.name = name;
            System.out.println("打开 " + name);
        }

        void query() {
            System.out.println("查询 " + name);
        }

        @Override
        public void close() {
            System.out.println("关闭 " + name);
        }
    }

    public static void main(String[] args) {
        try (Connection a = new Connection("A");
             Connection b = new Connection("B")) {   // 关闭顺序：B 再 A
            a.query();
            b.query();
        }
    }
}
```

自定义异常要保留原始 cause，catch 的备选项不能互为父子类型：

```java
public class ExceptionDemo {
    static class OrderException extends Exception {
        OrderException(String message, Throwable cause) {
            super(message, cause);            // 保留 cause，栈轨迹才完整
        }
    }

    static int parseQuantity(String raw) throws OrderException {
        try {
            int qty = Integer.parseInt(raw);
            if (qty <= 0) {
                throw new IllegalArgumentException("数量必须为正: " + qty);
            }
            return qty;
        } catch (IllegalArgumentException e) {   // NumberFormatException 是其子类
            throw new OrderException("数量解析失败: " + raw, e);
        }
    }

    public static void main(String[] args) {
        String[] inputs = {"3", "abc", "-1"};
        for (String input : inputs) {
            try {
                System.out.println("数量 = " + parseQuantity(input));
            } catch (OrderException e) {
                System.out.println(e.getMessage() + " <- " + e.getCause());
            }
        }
    }
}
```

`System.Logger` 输出结构化上下文，无需第三方依赖：

```java
import java.lang.System.Logger;
import java.lang.System.Logger.Level;

public class LoggingDemo {
    private static final Logger LOG = System.getLogger("demo.order");

    public static void main(String[] args) {
        String orderId = "ORD-2026-001";
        LOG.log(Level.INFO, "订单创建 orderId={0}", orderId);
        try {
            throw new IllegalStateException("库存不足");
        } catch (RuntimeException e) {
            LOG.log(Level.ERROR, "订单处理失败 orderId=" + orderId, e);
        }
    }
}
```

排查线上问题时，先 `jps -l` 找到 PID，再 `jstack <pid> > stack.txt` 抓取全部线程栈，用 `grep -A 30 "BLOCKED"` 找锁竞争，最后 `jcmd <pid> GC.heap_info` 看内存分布。

## 常见坑

- **`catch (Exception e) {}` 空吞异常**：问题被永久隐藏，至少记录日志并保留栈。
- **`e.printStackTrace()` 当日志**：输出到 stderr、无时间戳、无法分级，生产环境必须用日志框架。
- **异常当流程控制**：解析大量字符串时靠抛异常判断，会带来可观的性能开销。
- **丢失 cause**：`new RuntimeException(e.getMessage())` 会切断因果链，应传 `e` 本身。
- **`finally` 里 return 或抛异常**：会覆盖 `try` 中的返回值与异常。
- **包装异常时重复打印**：日志既打 `e.getMessage()` 又打 `e`，会重复输出整段栈。
