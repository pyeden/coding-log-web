# 04 车载以太网与 TSN

当带宽需求从"几十条信号"变成"几路摄像头加激光雷达点云"，CAN 的共享介质模型就到头了。车载以太网解决带宽问题，但带宽本身不产生确定性——真正让以太网能承载控制流量的是 TSN（Time-Sensitive Networking，时间敏感网络）这一组标准。把两者混为一谈，是做架构时最常见的概念滑坡。

## 本章目标

理解车载以太网的物理层选型与交换式拓扑，掌握 VLAN、优先级、时间同步与冗余机制的作用边界，能够判断哪些流量必须走 TSN 调度、哪些走尽力而为即可。

## 核心概念

**物理层** 与 IT 以太网不同。车载用单对双绞线：100BASE-T1 提供 100 Mbit/s，1000BASE-T1 提供 1 Gbit/s，10BASE-T1S 提供 10 Mbit/s 且支持多点共享，常用于替代低速 CAN 段。单对线的好处是重量与连接器成本，代价是链路预算更紧、对线束工艺更敏感。

**交换式拓扑** 取代了广播域。每个节点独占链路，交换机按 MAC 表转发。这消除了冲突，但也带来新的问题：交换机内部队列在拥塞时会丢帧，而车载功能往往不能接受丢帧。于是需要优先级与整形。

**VLAN（Virtual LAN，虚拟局域网）** 依据 IEEE 802.1Q 用 4 字节标签划分广播域。在车上，VLAN 的主要作用不是安全隔离的全部，而是把诊断、影音、控制流量分开，避免广播风暴波及控制域。

**TSN 的关键子集** 包括：IEEE 802.1AS 提供基于 gPTP 的时间同步，是所有时间调度的时间基准；IEEE 802.1Qbv 提供时间感知整形，用门控列表给关键流量预留时隙；IEEE 802.1CB 提供帧复制与消除（FRER），用冗余路径对抗单点链路故障。三者组合，才能让以太网具备接近总线的确定性。

## 关键设计与示例：交换机的端口配置

下面是一段说明性配置，表达"控制流量走时间窗、诊断流量限速"的思路，具体语法取决于交换机芯片与工具链：

```text
# 端口角色
port 1  uplink      # 上行至中央计算
port 2  camera      # 800万像素前视
port 3  radar
port 4  zonal-fl    # 区域控制器

# 802.1Q 划分
vlan 10 name control  ports 1,4
vlan 20 name sensor   ports 1,2,3
vlan 30 name diag     ports 1

# 优先级映射（PCP）
control -> pcp 5, sensor -> pcp 3, diag -> pcp 1

# 802.1Qbv 门控（示例时隙，需按实际周期对齐）
gate control : open 200us / 1000us
gate sensor  : open 700us / 1000us
```

时隙必须与 802.1AS 的同步周期对齐，否则门控会切断正在传输的帧。这就是为什么时间同步的精度直接决定调度能否成立：同步漂移超过保护带，关键帧会被截断。

## 关键设计与示例：带宽预算

一条 1000BASE-T1 链路扣除协议开销后，有效吞吐通常按 900 Mbit/s 量级估算。四路 800 万像素摄像头、每路压缩后按数十 Mbps 计，加上激光雷达点云，很容易吃掉大半带宽。此时要做的不是简单升级到更高速率，而是先问：这些数据必须在域控制器之间搬吗？能在传感器端做预处理吗？

| 流量类型 | 特征 | 建议机制 |
| --- | --- | --- |
| 控制指令 | 小包、周期稳定、低时延 | 802.1Qbv 时间窗 + 高优先级 |
| 传感器数据 | 大包、突发、可轻微丢帧 | 整形 + 适当缓冲 |
| 诊断刷写 | 大包、可降级 | 限速，避免挤占控制 |
| 时间同步 | 极短周期 | 最高优先级，硬件时间戳 |

## 常见坑

把 TSN 当"开了就确定性"。门控依赖全局同步与流量模型，配置错误会制造比不做调度更严重的抖动。

忽略交换机内部时延与队列。多级交换串联后，最坏时延是所有跳数与队列延迟之和，不能只看单跳指标。

用 IT 交换机做原型验证。缺少硬件时间戳与门控能力，测出的时延数据不能用于车载结论。

## 小结与参考

车载以太网给带宽，TSN 给确定性，VLAN 给隔离。三者是不同层面的工具，不能互相替代。参考 IEEE 802.1Q、802.1AS、802.1CB 与 802.1Qbv 标准文本，以及 IEEE 802.3 系列中的车载物理层规范；具体芯片能力以官方最新文档为准。
