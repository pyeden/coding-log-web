# 01 架构总览与核心术语

讨论架构之前先把词汇对齐。整车项目里最贵的沟通成本，往往不是技术分歧，而是两个团队对同一个词的理解不同：供应商说"网关"指的是中央网关，你以为是某个域控制器内部的转发模块；需求方说"信号"，写的是物理量，实现方理解成报文里的一个 bit 域。术语不清，后面所有评审都会在歧义上打转。

## 本章目标

建立一套可复用的 EEA 词汇表；理解节点、总线、网关、信号、PDU、服务之间的关系；能够读懂一张整车拓扑图并指出其中的单点与瓶颈。

## 核心概念

**节点（Node）** 是挂在总线上、拥有独立通信地址与诊断地址的电子控制单元（ECU，Electronic Control Unit）。一个 ECU 可以有多个应用，但通常只有一个网络身份。

**总线（Bus）** 是共享介质。CAN 是广播式多主结构，靠仲裁决定谁先发；LIN 是单主多从，靠调度表轮流发；以太网是交换式点对点，靠交换机转发。共享介质意味着带宽是被所有节点分摊的，这一点决定了架构的容量上限。

**网关（Gateway）** 承担跨网段转发与协议转换。它的价值不在"连通"，而在"隔离"：把诊断流量挡在动力网段之外，把不同波特率、不同协议的网络拼成一个逻辑整体。网关的转发时延与队列深度是整车响应链路上的固定开销。

**信号（Signal）与 PDU（Protocol Data Unit，协议数据单元）** 是报文承载的两种粒度。信号是带缩放与偏移的物理量，PDU 是打包后的字节块。经典 CAN 一帧最多 8 字节，CAN FD（Flexible Data Rate，灵活数据速率）可以到 64 字节，打包策略直接影响总线负载。

**通信矩阵（Communication Matrix）** 是架构与软件之间的合同：谁在什么周期发哪条报文、包含哪些信号、接收方是谁、超时怎么处理。它是 DBC、ARXML 等文件的源头，也是集成阶段定位"信号对不上"的第一份证据。

## 关键设计与示例：从需求到拓扑

一个典型的分层拓扑可以写成下面这样，箭头表示跨网段必须经过网关：

```text
   诊断口 OBD
      |
 [中央网关] --- 以太网骨干 --- [域控制器/区域控制器]
      |                              |
   CAN 动力网                     CAN 车身网
   |      |                        |      |
  VCU    BMS                     BCM    Door
```

读图时先找三样东西：网关的单点、每条总线的负载、以及哪些节点在失效后仍需工作。这张图里中央网关是通信单点，如果它掉电，诊断与跨域功能同时失效；如果项目要求跛行回家，就必须有备用路径或把关键转发下沉到区域控制器。

术语表按使用频率排列，建议在项目启动会上直接过一遍：

| 术语 | 英文全称 | 在架构中的位置 |
| --- | --- | --- |
| ECU | Electronic Control Unit | 最小可寻址控制单元 |
| EEA | Electrical/Electronic Architecture | 整车电气与电子的整体结构 |
| PDU | Protocol Data Unit | 报文中可打包的字节块 |
| DBC | CAN 数据库文件（业界通用格式） | 信号与报文的机读定义 |
| ARXML | AUTOSAR XML | 软件组件、服务与拓扑的机读定义 |
| UDS | Unified Diagnostic Services | 统一诊断服务，ISO 14229 |
| DoIP | Diagnostics over IP | 基于 IP 的诊断，ISO 13400 |

## 常见坑

把"信号"当"接口"。信号是传输细节，接口是契约。接口一旦以信号 bit 位置定义，任何重组报文都会变成跨团队改动。

把网关当透明管道。网关有队列、有优先级、有丢帧策略，高负载下的时延抖动必须实测，不能按理论带宽估算。

忽略诊断地址规划。诊断 ID 在项目早期看似随便分配，量产后与售后工具、OTA 平台、产线设备全部绑定，改一次牵动整条链路。

## 小结与参考

术语是架构的地基：节点给身份，总线给容量，网关给隔离，矩阵给合同。下一章把这套结构放进时间轴，看它如何从分布式走到中央计算。参考 ISO 11898 系列与 AUTOSAR 官方文档，具体版本以官方最新发布为准。
