# 11 诊断、刷写与整车 OTA

诊断协议在架构里承担两个看似无关的职责：售后排障与软件更新。二者共用同一套服务框架，但约束完全不同——诊断要求"能问清任何状态"，刷写要求"在有限带宽内可靠地换掉一整个软件"。把 OTA 当成"远程诊断"来做，会在失败恢复上吃大亏。

## 本章目标

掌握 UDS（Unified Diagnostic Services，统一诊断服务）的关键服务与会话模型，理解 DoIP（Diagnostics over IP）的适用场景，能够设计一套可回滚的整车 OTA 流程并核算升级时间。

## 核心概念

**UDS** 由 ISO 14229 定义，基于请求/响应模型。几个高频服务足以覆盖大部分场景：`0x10` 会话控制、`0x27` 安全访问、`0x22` 读数据、`0x2E` 写数据、`0x31` 例程控制、`0x34/0x36/0x37` 请求下载/传输数据/退出传输、`0x11` 复位、`0x3E` 保持连接、`0x19` 读故障码。

**会话与安全访问** 是两级门禁。默认会话只允许读；扩展会话开放例程与写入；编程会话用于刷写。安全访问用种子-密钥挑战，防止未授权写入。架构上必须明确"谁能进哪个会话"，否则产线工具与售后工具会互相踩权限。

**DoIP** 由 ISO 13400 定义，把诊断搬到 IP 上，使用固定的诊断端口。它的价值在大数据量：整车 OTA 通过 CAN 传几百 MB 不现实，而 DoIP 可以跑在百兆或千兆链路上。

**OTA 的关键不是下载，而是失败恢复**。A/B 双分区让新镜像写入非活动分区，校验通过后切换启动标志；若启动失败，引导程序回退到旧分区。差分升级能减少下载量，但增加了构建与校验复杂度，必须权衡。

## 关键设计与示例：一次典型刷写交互

```text
 tester -> ECU : 02 10 02            # 进入编程会话
 ECU    -> tester: 06 50 02 00 32 01 F4
 tester -> ECU : 02 27 01            # 请求种子
 ECU    -> tester: 06 67 01 AA BB CC DD
 tester -> ECU : 06 27 02 <key>      # 发送密钥
 ECU    -> tester: 02 67 02
 tester -> ECU : 10 34 00 44 ...     # 请求下载，指定地址与长度
 ECU    -> tester: 06 74 20 04 <maxBlock>
 tester -> ECU : 36 01 <data...>     # 逐块传输
 tester -> ECU : 02 37 01            # 退出传输
 tester -> ECU : 02 31 01 FF 00      # 校验例程
 tester -> ECU : 02 11 01            # 硬复位
```

首字节是服务号，第二字节常为子功能。负响应以 `0x7F` 开头，后跟服务号与 NRC（Negative Response Code），例如 `7F 27 35` 表示密钥无效。读 NRC 比猜现象快得多。

## 关键设计与示例：升级时间核算

```text
镜像大小：400 MB
链路：100BASE-T1，有效吞吐按 60 Mbit/s 估算
理论时间 ≈ 400 × 8 / 60 ≈ 53 s
实际时间 = 下载 + 校验 + 写入 + 切换 + 验证
```

实际往往是理论的数倍：写 Flash 的速度、校验算法、以及"逐个 ECU 串行升级"的策略都会拖长时间。架构上要决定并行度与用户可见的停机窗口——是允许车辆在升级期间不可用，还是要求"后台下载、驻车安装"。

差分升级与全量升级的选择同样要算总账。差分包的下载量小，但需要在产线或云端保存基线镜像、在车端做重建与校验，一旦基线版本错配就会生成不可用镜像。全量包简单可靠，代价是带宽与存储。工程上常见做法是：日常小版本用差分，重大版本或跨基线升级用全量，并把"校验失败即回退"作为硬约束写进引导程序。

## 常见坑

没有回滚路径。A/B 分区成本不高，但需要引导程序与标志位设计配合，事后加装几乎不可能。

忽略低压保护。刷写中途蓄电池电压跌落会导致镜像损坏，必须在流程里加入电压门限与中断恢复。

诊断与 OTA 抢带宽。整车升级时若诊断链路被占满，售后工具会频繁超时，需要优先级与限速策略。

## 小结与参考

UDS 给能力，DoIP 给带宽，A/B 给退路。三者缺一，OTA 就只是一次高风险的远程烧录。参考 ISO 14229 系列、ISO 13400 系列，以及整车厂诊断规范与 OTA 安全要求；具体服务支持范围以 ECU 诊断规范为准。
