# 智能驾驶

智能驾驶的工程本质，是把"感知世界的不确定性"转换成"可以接受的风险"。摄像头看不到被大车遮挡的路口，毫米波雷达分不清天桥与静止车辆，激光雷达在雨雾里回波衰减，这些都不是故障，而是系统的固有局限。所以这个领域真正的核心问题不是"能不能识别"，而是"识别不了的时候，系统知不知道我不知道"。

## 1. 领域定位与边界：一个闭环，三段不确定性

按功能拆，智能驾驶是一个闭环：感知回答"周围有什么"，预测回答"它们接下来会怎么动"，规划回答"我该怎么走"，控制回答"怎么把意图变成方向盘转角与制动压力"。按自动化程度拆，GB/T 40429《汽车驾驶自动化分级》把驾驶自动化分为 0 到 5 级，分级的核心不是功能多少，而是"谁在执行动态驾驶任务、谁在承担兜底责任"。

边界要划清。智驾不负责执行器的机械设计，但必须向底盘提出线控转向与线控制动的响应时间、冗余与失效模式要求；不负责座舱的交互设计，但必须与座舱共同定义接管请求的呈现方式；不负责整车网络拓扑，但会占用其中最宝贵的带宽与时间同步资源。智驾负责的是：在定义好的运行设计域内，把感知、决策、执行组织成一条可验证、可解释、可降级的安全链路。

三个目标互相拉扯。覆盖要广，就得处理更多长尾场景；安全要稳，就得在不确定时保守；成本要低，就得砍传感器与算力。行业里所有架构争论，本质都是"把不确定性放在哪一层消化"：放给传感器（多加一个激光雷达），放给算法（更大的模型），放给地图（更精确的先验），还是放给驾驶员（更早接管）。

最容易被低估的是"长尾的分布"。常见场景容易采集，也容易过拟合；真正致命的是低频但高后果的场景，比如施工路段的临时标线、侧翻的货车、突然横穿的行人。这类场景在数据里占比极低，却决定了系统的安全下限。

## 2. 流程中的位置

上游是产品定义与整车架构：目标市场、运行设计域、法规准入路径、成本带。下游是底盘执行、座舱交互、EEA 与测试验证。智驾的特殊之处是"软件定义、数据驱动"——硬件在方案阶段定型，能力却在量产之后靠数据与 OTA 持续生长。

| 阶段 | 智驾侧主要输入 | 关键输出 | 门禁关注点 |
| --- | --- | --- | --- |
| 产品定义 | 目标市场、用户场景、竞品能力 | 功能清单、运行设计域初稿、等级目标 | 法规可行性、责任边界 |
| 概念设计 | 整车布置、成本预算 | 传感器配置、算力平台、冗余方案 | 视野遮挡、清洗除霜、功耗散热 |
| 方案设计 | 供应商能力、算法路线 | 感知与规控架构、地图策略、数据闭环方案 | 场景覆盖度、算力余量、可解释性 |
| 详细设计 | 冻结数模、标定计划 | 传感器安装参数、软件模块、诊断与降级 | 时间同步、标定稳定性、安全分析 |
| 样车验证 | A/B/C 样车、场地与道路资源 | 仿真报告、场地测试、路测接管数据 | 接管率、误触发、边缘场景 |
| 工装试生产 | 产线节拍、下线检测 | 传感器标定工位、EOL 检测规范 | 标定一致性、一次通过率 |
| 量产运营 | 影子模式数据、用户反馈 | OTA 迭代、场景库扩充、事故复盘 | 回归不退化、版本可回滚 |

两个时点必须提前锁：运行设计域与传感器布置。前者决定了功能承诺的边界，后者牵动造型、风阻、清洗、碰撞与维修成本。等样车出来再补激光雷达，往往要重新做造型与碰撞仿真，代价远超预期。

## 3. 核心概念与术语表

| 术语 | 英文全称 | 一句话解释 |
| --- | --- | --- |
| 运行设计域 | Operational Design Domain (ODD) | 功能被设计为可安全运行的条件的集合 |
| 高级驾驶辅助系统 | Advanced Driver Assistance System (ADAS) | 以辅助驾驶员为目标的功能集合 |
| 自动紧急制动 | Autonomous Emergency Braking (AEB) | 在碰撞风险下自动施加制动 |
| 车道居中控制 | Lane Centering Control (LCC) | 持续控制转向使车辆保持在车道内 |
| 导航辅助驾驶 | Navigate on Autopilot (NOA) | 结合导航在高速或城区完成变道、进出匝道 |
| 行泊一体 | Integrated Driving and Parking | 行车与泊车共用一套感知与计算平台 |
| 鸟瞰图感知 | Bird's Eye View (BEV) | 把多视角图像统一到自车坐标系下的表示 |
| 占用栅格 | Occupancy Grid | 用体素描述空间中是否被占据，处理异形障碍物 |
| 多传感器融合 | Sensor Fusion | 把摄像头、毫米波雷达、激光雷达的信息合并 |
| 即时定位与地图构建 | Simultaneous Localization and Mapping (SLAM) | 边走边建图并同时定位 |
| 实时动态定位 | Real-Time Kinematic (RTK) | 利用基站差分把定位精度提升到厘米级 |
| 惯性测量单元 | Inertial Measurement Unit (IMU) | 测量加速度与角速度，弥补卫星定位遮挡 |
| 预期功能安全 | Safety of the Intended Functionality (SOTIF) | 无故障情况下因性能局限或误用产生的风险 |
| 汽车安全完整性等级 | Automotive Safety Integrity Level (ASIL) | 按严重度、暴露率、可控性划分的风险等级 |
| 影子模式 | Shadow Mode | 算法在后台运行但不执行，用真实数据评估表现 |
| 端到端 | End-to-End | 从传感器输入直接输出控制指令，减少手工模块划分 |

## 4. 主流方案与取舍

智驾方案的分岔集中在三个维度：传感器、地图、架构。

| 方案 | 主要优势 | 代价与限制 |
| --- | --- | --- |
| 纯视觉 | 成本低、数据规模大、语义理解强 | 逆光、雨雾、夜间与距离估计是硬约束 |
| 视觉加毫米波雷达 | 成本可控，测距测速稳定，全天候较好 | 静止目标与金属反射误判，融合标定要求高 |
| 视觉加激光雷达 | 三维几何精度高，异形障碍物识别好 | 成本与体积高，雨雾衰减，清洗与散热复杂 |
| 前融合 | 信息保留完整，理论上限高 | 时间同步与标定精度要求苛刻，可解释性差 |
| 后融合 | 模块独立、易调试、责任清晰 | 信息损失，冲突时仲裁规则难设计 |
| 高精地图方案 | 先验强，规控简单，舒适性好 | 覆盖与鲜度成本高，政策与资质约束 |
| 无图或轻图方案 | 泛化快、部署成本低、不依赖采集 | 对实时感知要求高，复杂路口稳定性挑战大 |
| 模块化架构 | 可解释、可定位、便于功能安全论证 | 模块间信息损失，长尾优化靠人工堆规则 |
| 端到端架构 | 上限高、迭代快、减少手工规则 | 可解释性弱、验证困难、责任界定复杂 |
| 行泊一体 | 共用硬件，成本与体积占优 | 场景差异大，算力调度与安全隔离复杂 |
| 行车与泊车分离 | 各自优化充分，风险隔离 | 硬件重复，成本与重量上升 |

判断方案是否合适，看三个问题：目标场景的分布是否支撑这个选择；失效时的降级是否有明确的接管链路；以及验证成本是否在预算内。纯视觉在数据充足、道路结构化程度高的市场很有竞争力，但在逆光与强降雨频发的市场，雷达的稳定性就是刚需。方案没有绝对先进，只有与运行设计域匹配与否。

端到端是近几年的热点，但工程上要看清它改变的是"上限"，不是"下限"。它可以减少手工规则、提升拟人化程度，却让"为什么这么决策"更难回答。可行的路径通常是混合：感知用端到端提升上限，规控保留可解释的安全兜底与规则约束。

## 5. 关键交付物与评审要点

交付物分四类。**定义类**：功能清单、运行设计域文档、人机共驾与接管策略、责任边界说明。**安全类**：危害分析与风险评估、安全目标与安全概念、预期功能安全分析、安全论证文档、降级与最小风险状态策略。**验证类**：场景库与覆盖率报告、仿真测试报告、封闭场地测试报告、公开道路测试里程与接管统计、误触发与漏触发分析。**运营类**：数据记录系统规范、影子模式评估报告、OTA 回归测试、事故复盘流程。

评审最该盯三件事。其一，运行设计域之外的场景怎么处理：是明确退出并请求接管，还是"装作能开"。其二，接管请求的时序是否留够：从提示到接管，驾驶员的反应时间必须用实测分布来定，而不是拍一个数字。其三，验证是否只证明了"能通过"，而没有证明"不会误触发"：一个频繁误刹的系统，用户会关掉它，安全收益归零。

还有一条常被忽略：安全论证要能回答"为什么这些测试足够了"。里程数不是证据本身，场景覆盖与风险分解才是。用少量高风险场景加大量仿真，比单纯堆里程更有说服力。

## 6. 标准法规与工具链

国内基础标准：GB/T 40429-2021《汽车驾驶自动化分级》给出分级框架；GB 44497-2024《智能网联汽车 自动驾驶数据记录系统》对数据记录提出要求；GB 44495-2024 与 GB 44496-2024 分别约束整车信息安全与软件升级。准入层面，工信部等部门开展的智能网联汽车准入和上路通行试点，对产品测试、安全评估与责任承担提出了组合要求，具体条件以最新官方发布为准。

国际方面：UN R157 针对车道保持类自动车道保持系统，UN R79 约束转向装置，UN R152 针对自动紧急制动；ISO 26262 覆盖功能安全，ISO 21448 覆盖预期功能安全，ISO 34502 提供基于场景的安全评估框架，ISO/SAE 21434 覆盖网络安全。标准引用时务必核对版本与适用范围，二手文章里的年份经常出错。

工具链分四层。仿真：CARLA、IPG CarMaker、VTD、PreScan 一类平台，配合场景生成与交通流模型；数据：采集车、标注平台、数据版本管理、场景挖掘与回放；训练：PyTorch 一类框架加推理加速工具链；测试与标定：dSPACE 或 Vector 的 HIL、CANoe 做总线与诊断、GNSS 模拟器与暗室。工具的真实成本不在 license，而在数据管道与标注质量。

## 7. 与其他领域的接口冲突

**与底盘的接口**：智驾的输出最终落在转向、制动与驱动上，线控系统的响应延迟、死区与冗余直接决定控制品质（见[底盘系统](/note/chassis/)）。典型冲突是"控制权交接"：驾驶员转方向盘时，系统是立即退出还是软对抗，退出时的力矩突变会让驾驶员受惊。这需要在底盘与规控之间定义统一的交接状态机，而不是各写一套。

**与 EEA 的接口**：摄像头、雷达、激光雷达的数据量与时延要求，把整车骨干网推向高带宽以太网与精确时间同步（见 [EEA 学习笔记](/note/eea/)）。冲突是资源竞争与故障传播：一个域控的异常复位不应该让整车网络抖动，感知数据也不应该挤掉制动指令。解决靠流量整形、时间敏感网络与域间隔离，并在架构阶段就做最坏情况带宽核算。

**与座舱的接口**：接管请求、功能状态、感知可视化都要通过仪表与 HUD 呈现（见[智能座舱](/note/cockpit/)）。冲突是信息过载：智驾想显示更多"我看到的东西"来建立信任，座舱却要控制总信息量避免分心。可行的做法是分层显示——常态只给状态与关键目标，异常时再升级提示，并把升级规则写成双方共同的规范。

**与热管理的接口**：域控与激光雷达都是高热流密度部件，夏季长时间运行会触发降频甚至降级（见[热管理](/note/thermal/)）。冲突是"最需要算力时最热"：正午高速巡航恰恰是感知最复杂的工况。设计上要么提高散热规格，要么在热受限时降级功能并明确告知，不能悄悄降低感知帧率。

**与整车安全的接口**：智驾的制动与转向会改变碰撞形态，安全气囊点爆、安全带预紧与主动安全的时序需要联合标定（见[整车安全与法规](/note/vehicle-safety/)）。冲突是"主动安全与被动安全抢时间"：AEB 把车刹停，可能让本应触发的被动保护失去意义，也可能避免一次碰撞。这需要统一的碰撞风险判断与执行优先级。

**与汽车软件的接口**：智驾大量使用自适应 AUTOSAR 做通信与执行管理，诊断、刷写与日志要接入整车体系（见[汽车软件与 AUTOSAR](/note/autosar/)）。冲突是"两套时间基准"：感知用传感器时间戳，执行用总线周期，融合不好会让控制出现周期性抖动。统一时间同步方案比任何单点优化都重要。

**与整车开发的接口**：运行设计域一旦写进宣传与法规文件，就成为对用户的承诺（见[整车开发流程与项目管理](/note/vehicle-dev/)）。冲突是市场想多说、工程想少承诺：把"支持某城市"写成"全国都能开"，最后买单的是售后与法务。运行设计域的措辞要在上市前由工程、法务、市场三方共同签字。

## 8. 常见坑与检查清单

- [ ] 运行设计域是否写清了天气、光照、道路类型、地理范围与交通条件，而不是一句"高速与城区"
- [ ] 传感器安装位置是否考虑遮挡、脏污、清洗、除霜与碰撞维修，标定参数是否可离线复现
- [ ] 多传感器时间同步是否做到统一时间基准，最坏偏差是否有量化指标
- [ ] 接管请求的提前量是否用驾驶员反应时间实测分布确定，并覆盖分心与疲劳状态
- [ ] 降级与最小风险策略是否定义了"感知失效、定位丢失、算力不足"三种情形的具体动作
- [ ] 影子模式的数据回传是否合规，是否做了脱敏与地理信息处理
- [ ] 误触发率与漏触发率是否分别统计，而不是只报"避免了多次碰撞"
- [ ] OTA 升级后是否做回归测试，是否验证过旧版本回滚与新老版本共存

## 9. 学习路径与资料

建议按"几何、概率、系统"三段走。先补几何与视觉基础：相机模型、坐标系变换、标定、多视图几何；再补概率与估计：卡尔曼滤波、粒子滤波、多目标跟踪、数据关联；最后补系统与安全：功能安全、预期功能安全、场景化验证、责任与法规。

资料优先级：国家标准与法规原文高于 ISO 与 SAE 标准正文，高于顶会论文与开源项目文档，高于媒体评测。论文告诉你方法的上限，标准告诉你产品的下限，两者都不能省。

实践建议：先用开源数据集跑通一个完整的感知到控制链路，理解每个环节的误差如何累积；再跟一次封闭场地测试，看测试工程师如何设计"能复现失败"的场景；最后读一份真实的事故复盘报告，你会对"接管"两个字有完全不同的理解。

最后提醒：智驾的宣传语与工程能力之间永远有落差。看一个系统，不要看它演示了什么，要看它在什么条件下会退出、退出前给多久、退出后谁负责。这三个问题的答案，比任何参数都更能说明水平。
