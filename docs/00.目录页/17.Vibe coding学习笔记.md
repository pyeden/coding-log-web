## 这套笔记解决什么问题

用 AI 写代码的门槛已经很低，难的是**让产出的代码可以被合并、被维护、被追责**。这套笔记不讨论「哪个模型更强」，而是把 Vibe coding 当成一条工程流水线：先讲清定义与边界，再选工具、备上下文、定流程，最后用测试与评审把质量兜住。

## 阅读顺序

1. **导读：Vibe coding 是什么**：先读。建立「人负责意图与验收」的基本框架，理解四类风险与三道闸门。
2. **工具链与选型**：按交互形态而非品牌选工具，附决策树。
3. **上下文工程与规格驱动**：仓库地图、规则文件、任务卡与验收标准。
4. **从需求到合并的工作流**：六步闭环、提示词模板、diff 审查与回滚。
5. **质量、安全与团队落地**：测试护栏、依赖与密钥、度量与三阶段落地路线。

时间有限时，按 00 → 03 → 04 阅读即可覆盖「怎么做」与「怎么不出事」。
