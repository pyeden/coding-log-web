## 这套笔记解决什么问题

会用 LangChain 不等于会写 LLM 应用。真正的分界线在三个地方：知道每个抽象住在哪一层，所以报错能查；知道一次调用的数据流，所以效果差能定位；知道什么时候不该用它，所以不会为了框架而框架。

这套笔记按「地图 → 地基 → 部件 → 工程」的顺序组织：先讲包分层与运行时，再讲 Runnable 与 LCEL，然后把模型、检索、Agent、记忆、观测逐个拆开，最后回到流式、并发、成本与版本管理这些上线才会暴露的问题。

## 阅读顺序

1. **导读：为什么读 LangChain**：定位、边界、版本演进与阅读路线。
2. **架构总览：包分层与运行时**：每个模块住在哪层，一次 `invoke` 发生了什么。
3. **核心抽象：Runnable 与 LCEL**：全书地基，一条链为什么同时具备流式与并发。
4. **模型层：ChatModel、消息与结构化输出**：每天都要用的部分。
5. **检索与 RAG：从文档到上下文**：切分、嵌入、检索策略与评估。
6. **工具与 Agent：从 ReAct 到 LangGraph**：循环的本质与不可逆操作的闸门。
7. **记忆与状态：会话、Checkpointer 与存储**：多轮与跨会话的设计原则。
8. **可观测与评测：Tracing 与数据集评估**：让优化从猜测变成度量。
9. **工程化：流式、并发、成本与常见坑**：上线前的检查清单。

时间有限时，按 00 → 02 → 03 → 08 阅读可以覆盖「怎么写」与「怎么不出事」。
