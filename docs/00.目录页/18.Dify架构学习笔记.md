## 这套笔记解决什么问题

会调用模型 API，不等于会做 LLM 应用。从一次对话到一套可运营的系统，中间隔着应用形态、工作流编排、知识库索引、模型与工具接入、异步任务、多租户和部署边界。这套笔记以 Dify 1.13.3 的源码为样本，把这些问题拆开讲：不背功能清单，而是看请求怎么流动、状态放在哪里、扩展点如何划定。

## 阅读顺序

1. **导读：为什么要读 Dify 的架构**：先读。理解它补齐的入口、编排、知识与运营四段，以及三条阅读线。
2. **全景：从应用到 LLMOps 平台**：monorepo、六层结构、compose 拓扑与单机/生产拆分。
3. **应用运行时：六种形态与一次请求**：AppMode 差异、一次聊天从入口到 SSE 的全链路、草稿与发布。
4. **Workflow 引擎：图、变量池与执行**：graphon、节点注册、变量引用、分支迭代与失败处理。
5. **RAG 与知识库：从文档到召回**：解析、切分、索引、召回、重排，以及常见坑。
6. **模型、插件与工具：能力如何外挂**：六类模型、插件守护进程、四类工具与降级策略。
7. **数据、任务与部署：后台作业与运维边界**：四类存储、Celery 任务、多租户与安全边界。
8. **架构心得：可复用的设计取舍**：八条原则、反例与「如果我来设计」清单。

时间有限时，按 00 → 01 → 02 → 07 阅读：先建立全景与请求主线，再直接看可复用的取舍。
