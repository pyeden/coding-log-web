## 这套笔记解决什么问题

自动化测试最常见的失败不是「不会写脚本」，而是**选错了层**：用 UI 自动化去覆盖本该由接口测试守护的业务规则，结果用例又慢又碎，改一次前端样式就红一片。这套笔记先讲边界与选型，再分别落到四类被测对象上，最后统一收口到工程化：定位策略、等待策略、数据治理、报告与 CI 门禁。

## 阅读顺序

1. **导读与自动化选型**：先读。确定你的团队该在哪一层投入，避免一上手就写 UI 脚本。
2. **Web 自动化教程**：浏览器端到端，以 Playwright 为主线。
3. **API 自动化教程**：接口契约与业务规则的主力层，投入产出比最高。
4. **Android 自动化教程**：Appium 2 + UiAutomator2。
5. **iOS 自动化教程**：XCUITest 主线，Appium XCUITest driver 作跨端方案。

Android 与 iOS 两篇共用同一套「页面对象 + 显式等待」的思路，建议对照阅读。
