## 这篇总结解决什么问题

这不是一份 API 速查，而是一份踩坑后的工程复盘。它回答四个问题：模型为什么会在 HTTP 200 时返回空内容；重试为什么越试越慢；计划为什么一执行就 404；以及模型说“成功了”时，系统凭什么相信。

内容来自 MacBook 节点上 PanguVerse、coding-log-web 与几个站点工具项目的真实日志，覆盖模型层、请求层、上下文层、规划层、验证层和产品层。

## 阅读顺序

1. **故障面地图**：先建立分层排查顺序，避免一上来就改 prompt。
2. **推理模型与输出预算**：`max_tokens`、reasoning、`finish_reason=length` 的关系。
3. **重试与总预算**：超时、步数、退避和剩余预算如何联动。
4. **JSON 模式**：空响应、代码块、解释文字与一次修复重试。
5. **先观察后计划**：模板假设、沙箱可见性与 explore-first。
6. **确定性验证**：成功标准、重放与发布门禁。
7. **无 LLM 降级**：哪些场景不该用模型。
8. **上下文、权限与可观测性**：模型能看到什么、能做什么、留下了什么证据。
9. **上线检查清单**：上线前逐条打勾。
