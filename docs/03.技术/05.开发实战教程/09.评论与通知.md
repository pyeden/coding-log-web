# 09. 评论与通知

## 这一章解决什么

让读者能评论、回复，让作者知道“有人评论了我的文章”。

## 评论模型

```python
class Comment(models.Model):
    article = models.ForeignKey(Article, on_delete=models.CASCADE, related_name="comments")
    user = models.ForeignKey(User, on_delete=models.CASCADE, related_name="comments")
    body = models.TextField()
    parent = models.ForeignKey("self", on_delete=models.CASCADE, null=True, blank=True, related_name="replies")
    active = models.BooleanField(default=True)
```

只做两级：回复某条回复时，归到它的根评论下。这样树不会无限深，前端缩进也可控。

## 评论接口

- `GET /api/articles/:slug/comments/` 返回根评论数组，每条带 `replies`。
- `POST` 接收 `{body, parent_id?}`，登录才能发。
- `DELETE /api/comments/:id/` 作者或 staff 才能删，软删除 `active=False`。

父评论必须属于同一篇文章，否则返回 400；跨文章回复是脏数据。

## 通知

评论创建后，如果评论者不是文章作者，创建一条通知：

```python
Notification.objects.create(
    recipient=article.author, actor=request.user,
    verb="commented", target_article=article, target_comment=comment,
)
```

通知列表返回最近 20 条和 `unread_count`；支持单条已读和全部已读。前端导航栏的小红点只显示数量，不轮询太频繁；60 秒一次，页面重新可见时刷新。

## 前端评论树

`CommentTree` 渲染根评论，`CommentNode` 递归渲染 `replies`。每条评论显示头像、用户名、时间、正文、回复/删除按钮。回复表单在节点内展开，提交后重新拉取整棵树。

## 删除与审核

删除是软删除，保留记录但不显示。没有做后台审核队列；如果评论被滥用，先在 Django admin 里把 `active` 改为 False，后续再加举报和审核。

## 验证

- 登录后评论成功，文章作者收到通知。
- 自己评论自己的文章不产生通知。
- 回复一条回复，挂在根评论下。
- 删除评论后列表不再显示。

## 坑

评论树递归序列化时容易 N+1。当前用 `select_related` + 递归查询，评论量大时应改成一次性取全树再在内存组装。

## 小结

评论是读者和作者的连接，通知是这条连接的提醒。先把“能评论、能看到、能删”做对，再考虑表情、审核和邮件。
