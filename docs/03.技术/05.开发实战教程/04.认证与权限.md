# 04. 认证与权限

## 这一章解决什么

让用户能注册、登录、退出、改资料、重置密码、删除账号，并保证“只有作者能改删自己的文章”。

## 为什么用 Session

DRF 默认支持 Session 和 Token。这个项目选 Session + CSRF：

- 浏览器自动带 cookie，前端不用存 token。
- CSRF 防跨站写请求。
- 退出登录就是删 session，逻辑简单。

代价是前后端必须处理 CSRF cookie 和登录后的 token 轮换。

## CSRF

```python
class CsrfView(APIView):
    permission_classes = [AllowAny]

    @method_decorator(ensure_csrf_cookie)
    def get(self, request):
        return Response({"csrfToken": get_token(request)})
```

前端启动时先 `GET /api/auth/csrf/`，之后所有写请求带 `X-CSRFToken`。登录成功后 Django 会轮换 token，必须再取一次。

## 注册与登录

```python
class LoginView(APIView):
    def post(self, request):
        user = authenticate(request, username=request.data.get("username"), password=request.data.get("password"))
        if user is None:
            return Response({"detail": "用户名或密码错误。"}, status=400)
        login(request, user)
        return Response({"user": UserSerializer(user, context={"request": request}).data})
```

注册用 `RegisterSerializer`：用户名唯一、两次密码一致、走 Django 的密码强度校验。注册成功直接 `login()`，用户不用再登录一次。

## 对象权限

```python
class IsAuthorOrStaff(permissions.BasePermission):
    def has_object_permission(self, request, view, obj):
        if request.method in permissions.SAFE_METHODS:
            return True
        return request.user.is_authenticated and (request.user.is_staff or obj.author_id == request.user.id)
```

列表接口用 `IsAuthenticatedOrReadOnly`，详情/改/删再叠对象权限。不要只在视图里 `if` 一下，DRF 的权限类会被所有 action 复用。

## 用户资料与头像

`Profile` 与 `User` 一对一。`ProfileView` 支持 GET/PATCH，头像单独 multipart 上传：

```python
def post(self, request):
    profile, _ = Profile.objects.get_or_create(user=request.user)
    profile.avatar = request.FILES["avatar"]
    profile.save(update_fields=["avatar"])
```

## 密码重置

`PasswordResetView` 生成 `uid` + `token`，用 Django 的 `default_token_generator`。开发环境用 console backend，邮件会打印在后端终端；生产要配 SMTP。

确认接口：

```python
class PasswordResetConfirmView(APIView):
    def post(self, request):
        user = User.objects.get(pk=urlsafe_base64_decode(request.data["uid"]).decode())
        if not default_token_generator.check_token(user, request.data["token"]):
            return Response({"detail": "重置链接已失效。"}, status=400)
        user.set_password(request.data["password"])
        user.save()
```

## 删除账号

要求再次输入密码，删除前先 `logout()`。`Article.author` 是 `CASCADE`，文章、评论、通知会一起删除，前端必须把后果说清楚。

## 验证

- 未登录 `POST /api/articles/` 返回 403。
- 非作者 `PATCH` 返回 403。
- demo 登录后 `GET /api/auth/me/` 返回用户。
- 密码错误删除账号返回 400。

## 小结

认证解决“你是谁”，权限解决“你能做什么”。两件事分开想，代码会清楚很多。下一章进前端。
