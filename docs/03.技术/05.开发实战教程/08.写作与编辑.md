# 08. 写作与编辑

## 这一章解决什么

让作者在浏览器里写完一篇文章，包括标题、正文、栏目、标签和封面。

## 编辑器结构

`ArticleEditor` 左侧是表单，右侧是实时预览：

- 标题输入。
- 栏目下拉，数据来自 `/api/columns/`。
- 标签输入，回车添加，最多 10 个。
- 封面选择，本地预览。
- Markdown textarea。
- 工具栏：H1/H2、粗体、斜体、链接、代码块、引用、列表。

工具栏通过 `selectionStart/selectionEnd` 在光标处插入标记，不引入重型编辑器依赖。

## 实时预览

预览使用 `marked + DOMPurify`，和详情页的最终渲染保持视觉一致。保存时提交的是 Markdown 源文，后端统一渲染 `body_html`；不要提交预览 HTML，否则再次编辑会把 HTML 当 Markdown。

## 创建与更新

```js
const saved = isEdit
  ? await updateArticle(article.slug, payload)
  : await createArticle(payload)
if (coverFile.value) await uploadArticleCover(saved.slug, coverFile.value)
```

封面单独走 multipart 的 `POST /api/articles/:slug/cover/`。这样创建文章的 JSON 不需要和文件混在一起，编辑器逻辑更清楚。

## 权限

- 未登录访问 `/write` 被路由守卫送到登录页。
- 编辑页只对作者或 staff 显示保存按钮；后端仍会校验，前端隐藏只是体验。
- 删除文章用 `window.confirm`，文案明确“不可恢复”。

## 编辑已有文章

`EditArticleView` 先请求详情，把 `title/body/column/tags/cover` 回填。`body` 用源文，不用 `body_html`。保存走 PATCH，只提交表单里的字段。

## 验证

- 新建文章后详情页立即能打开。
- 编辑标题后 slug 不变，旧链接仍有效。
- 上传封面后列表和详情显示新图。
- 非作者打开编辑页，保存返回 403。

## 坑

- 清除栏目时传 `null`，不要传空字符串；序列化器对 `null` 的处理更明确。
- 封面文件类型只做前端 `accept` 不够，后端仍应校验图片。
- 编辑器没有自动保存，长文要养成手动保存草稿的习惯。

## 小结

写作端的目标是“输入不打断思路”。功能可以少，但保存、预览、封面这三件事必须可靠。下一章处理评论与通知。
