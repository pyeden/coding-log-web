# 03. API 设计

## 这一章解决什么

把模型暴露成前端能用的 JSON 接口，并统一分页、过滤和错误形状。

## 路由

所有接口挂在 `/api/` 下：

```python
urlpatterns = [
    path("admin/", admin.site.urls),
    path("api/health/", health),
    path("api/", include("accounts.urls")),
    path("api/", include("blog.urls")),
    path("api/", include("comments.urls")),
    path("api/", include("notices.urls")),
]
```

文章用 DRF 的 `ViewSet` + `SimpleRouter`：

```python
router = SimpleRouter()
router.register("articles", ArticleViewSet, basename="article")
```

## 序列化器

列表和详情共用 `ArticleSerializer`，但只读字段要明确：

```python
class ArticleSerializer(serializers.ModelSerializer):
    author = AuthorSerializer(read_only=True)
    column = ColumnField(required=False, allow_null=True)
    tags = TagsField(required=False)
    cover = serializers.SerializerMethodField()
    excerpt = serializers.SerializerMethodField()
    comment_count = serializers.SerializerMethodField()
    body_html = serializers.CharField(read_only=True)
    toc = serializers.SerializerMethodField()
    liked = serializers.SerializerMethodField()
```

`tags` 接受字符串数组，`column` 接受 slug 或 id。创建时作者从 `request.user` 取，不能让前端传作者。

## 分页

```python
class DefaultPagination(PageNumberPagination):
    page_size = 6
    page_size_query_param = "page_size"
    max_page_size = 50
```

响应形状统一为 `{count, next, previous, results}`。前端只认这一种，不要有的接口返回裸数组、有的返回分页对象。

## 过滤

```python
search_fields = ["title", "body"]
ordering_fields = ["created", "updated", "total_views", "likes", "title"]
```

栏目和标签在 `get_queryset()` 里处理：

```python
if column:
    queryset = queryset.filter(Q(column__slug=column) | Q(column__id=column))
if tag:
    queryset = queryset.filter(Q(tags__name__iexact=tag) | Q(tags__slug__iexact=tag)).distinct()
```

标签过滤必须大小写不敏感，也要同时接受 name 和 slug。否则 `Django` 和 `django` 会变成两个世界。

## 错误形状

DRF 默认返回 `{field: [msg]}` 或 `{detail: msg}`。前端 `apiError()` 统一解析，不要把 Django 的 HTML 错误页直接展示给用户。

## 验证

```bash
curl -s http://127.0.0.1:8000/api/articles/ | python3 -m json.tool | head
curl -s http://127.0.0.1:8000/api/articles/?tag=django
```

## 小结

API 是前后端之间的合同。合同稳定，页面才好写。下一章处理认证与权限。
