# 00. 先想清楚要做什么

## 这一章解决什么

动手写代码前，先回答一个问题：这个博客到底为谁、解决什么？如果答案是“什么都想做”，最后通常什么都做不深。

我给它的边界是：

- 一个人写，一个人维护。
- 读者能安静地读长文，不被弹窗和推荐流打断。
- 作者能在浏览器里写完、改完、发出去。
- 评论和通知够用，但不做复杂社交。
- 能挂在一个已有域名的子路径下，不额外买服务器。

## 页面清单

把页面先列出来，后面的模型和 API 就不会散：

1. 首页：最新文章、最热文章、栏目、标签、搜索入口。
2. 文章详情：正文、目录、点赞、评论、作者操作。
3. 写作/编辑：Markdown、实时预览、封面、栏目、标签。
4. 登录、注册、找回密码。
5. 个人资料：简介、电话、头像、删除账号。
6. 搜索、栏目归档、标签归档。
7. 通知中心。
8. 404。

## 技术分工

- Django：用户、权限、后台、ORM、Markdown 渲染、邮件令牌。
- DRF：把模型变成 JSON API。
- Vue：路由、状态、页面交互、编辑器。
- nginx + gunicorn：静态资源与动态 API 分开处理。

前后端分离不是为了时髦，而是为了让“写作端”和“阅读端”可以独立演进。今天想改首页布局，不需要动 Django 的视图；明天想加一个 API 字段，也不需要改模板。

## 验收标准

项目做完时，下面这些必须成立：

- 未登录能读，登录后能写；非作者不能改删。
- Markdown 渲染后没有 XSS，代码块可读。
- 点赞重复点不会把计数刷上去。
- 评论是两级树，作者能收到通知。
- 刷新任意前端路由不 404。
- 生产 `DEBUG=False`，密钥不进仓库。
