# 12. 部署到子路径

## 这一章解决什么

把本地两个工程变成一个可访问的线上站点：`https://seres-ai.com/djangovueblog/`。

## 构建与打包

前端在开发机构建：

```bash
cd frontend
VITE_BASE=/djangovueblog/ VITE_API_BASE=/djangovueblog/api npm run build
```

`dist/` 放到 release 的 `frontend/djangovueblog/`。后端只复制代码，不带 `.venv`、数据库、日志和媒体。

## 运行时

Mac mini 上：

- Python 3.12 venv：`/Users/mac/djangovueblog-runtime/venv`
- 数据目录：`/Users/mac/djangovueblog-data`（SQLite、media、日志、env）
- release：`/Users/mac/djangovueblog-releases/<timestamp>-<sha>`，`current` 软链到最新
- gunicorn：`127.0.0.1:8899`，3 workers，launchd 守护

`run.sh` 先 source 环境变量，再 exec gunicorn；密钥不写进 plist。

## nginx 子路径

```nginx
location /djangovueblog/api/ {
    proxy_pass http://127.0.0.1:8899/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location /djangovueblog/media/ {
    alias /Users/mac/djangovueblog-data/media/;
}

location /djangovueblog/static/ {
    alias /Users/mac/djangovueblog-releases/current/staticfiles/;
}

location /djangovueblog/ {
    root /Users/mac/djangovueblog-releases/current/frontend;
    try_files $uri $uri/ /djangovueblog/index.html;
}
```

`proxy_pass` 末尾的 `/` 会去掉 `/djangovueblog/api/` 前缀。SPA 刷新靠 `try_files` 回退，否则 `/article/xxx` 会 404。

## Django 生产配置

- `DEBUG=False`
- `ALLOWED_HOSTS=seres-ai.com,127.0.0.1,localhost`
- `CSRF_TRUSTED_ORIGINS=https://seres-ai.com`
- `SECURE_PROXY_SSL_HEADER=("HTTP_X_FORWARDED_PROTO","https")`
- `DJANGO_STATIC_URL=/djangovueblog/static/`
- `DJANGO_MEDIA_URL=/djangovueblog/media/`

少了 `X-Forwarded-Proto`，Django 会以为请求是 http，Secure cookie 和绝对 URL 都会出问题。

## 上线流程

1. 开发机构建前端、打包后端。
2. rsync 到部署机 release。
3. 安装依赖、migrate、collectstatic。
4. 切 `current`，重启 launchd 服务。
5. 健康检查 `127.0.0.1:8899/api/health/`。
6. nginx reload（需要管理员权限）。
7. 公网验收：首页、API、静态资源、SPA 深层路由、登录/评论/点赞。

## 验证

```bash
curl -I https://seres-ai.com/djangovueblog/
curl https://seres-ai.com/djangovueblog/api/health/
```

都应返回 200；刷新任意详情链接也不应 404。

## 小结

部署的难点不是命令，而是路径、权限和协议。把“构建、运行、代理、回退”四件事分开检查，问题会好定位得多。下一章复盘。
