# 05. 前端工程与视觉系统

## 这一章解决什么

让前端不只是“能跑”，而是有一套稳定的布局、颜色和交互规则，后面写页面时不用每次重新决定间距和字号。

## 工程结构

```text
src/
├── api/          axios 与接口封装
├── assets/       全局样式
├── components/   可复用组件
├── router/       路由
├── stores/       Pinia
├── utils/        格式化与 Markdown
├── views/        页面
├── App.vue
└── main.js
```

页面和组件分开：页面负责取数和路由参数，组件负责展示与交互。这样详情页、归档页可以复用同一张文章卡片。

## Vite 配置

开发环境 `base=/`，生产 `base=/djangovueblog/`；`/api` 代理到 Django 的 8000：

```js
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '')
  return {
    base: env.VITE_BASE || '/',
    server: { proxy: { '/api': { target: env.VITE_PROXY_TARGET || 'http://127.0.0.1:8000' } } },
  }
})
```

生产构建时 `VITE_API_BASE=/djangovueblog/api`，前端所有请求都带子路径，不需要在代码里写死域名。

## 设计 token

颜色和字体集中在 `main.css` 的 `:root`：

```css
:root {
  --paper: #faf6ee;
  --ink: #211d18;
  --muted: #6f6559;
  --accent: #a9482a;
  --line: #e4dccd;
  --serif: "Iowan Old Style", Georgia, "Songti SC", serif;
  --sans: -apple-system, "PingFang SC", sans-serif;
}
```

暖纸色背景、墨色正文、砖红强调色。标题用衬线体，正文用无衬线；强调色只出现在链接、按钮、当前目录和少量编号上，避免整页花掉。

## 路由与状态

路由表覆盖首页、详情、写作、编辑、登录、注册、重置密码、资料、搜索、栏目、标签、通知、404。`requiresAuth` 和 `guestOnly` 在 `beforeEach` 里统一处理，页面里不再重复判断。

Pinia 分四个 store：

- `auth`：当前用户、登录态、bootstrap。
- `notifications`：未读数量与列表。
- `meta`：栏目和标签，避免每个页面重复请求。
- `toast`：全局提示。

## 布局

桌面端是“主内容 + 侧栏”，侧栏 sticky；移动端侧栏落到内容下方。文章详情是“正文 + 目录”，目录在窄屏隐藏。编辑器是左右分栏，窄屏上下堆叠。

## 验证

```bash
npm run build
```

构建产物应包含 `index.html` 和 `assets/*.js/css`，没有 CSS 404。浏览器里检查：首页两栏、详情目录、编辑器预览、移动端断点。

## 小结

视觉系统不是“美化”，而是减少每次写页面的决策成本。下一章开始写首页。
