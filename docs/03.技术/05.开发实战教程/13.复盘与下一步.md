# 13. 复盘与下一步

## 已经做成的

- 文章、栏目、标签、封面、分页、搜索、最热、浏览量、点赞。
- 两级评论、通知、注册/登录、资料、头像、密码重置、删除账号。
- 51 个后端测试、17 项 API 冒烟、前端构建与页面验收。
- gunicorn + launchd + nginx 子路径部署。

## 设计上做对的地方

1. **前后端分离**：Django 只管数据和权限，Vue 只管页面。改首页不用碰后端。
2. **服务端点赞**：唯一约束保证幂等，比浏览器 localStorage 可靠。
3. **Markdown 服务端渲染**：统一 `body_html`，详情页不用每次跑解析器，也能统一清洗。
4. **子路径部署**：复用既有域名和证书，不额外买服务器。
5. **测试覆盖权限**：匿名、作者、非作者、staff 都测，避免“功能能跑但谁都能删”。

## 还没做或做得不够的

- GitHub OAuth 未启用；需要 OAuth App 凭据和回调配置。
- 密码重置默认 console backend，生产未配 SMTP。
- 文章上下篇快捷导航未实现，详情页用目录和侧栏替代。
- 评论通知只覆盖“评论文章”，回复评论和点赞不发通知。
- 评论树查询有 N+1，评论量大时要一次性取全树。
- SQLite 适合个人博客，未做 PostgreSQL/MySQL 迁移与备份。
- 没有前端组件测试和端到端测试。
- 没有图片压缩、缩略图、对象存储。

## 下一步优先级

1. 配 SMTP，让密码重置真正可用。
2. 加图片压缩和缩略图，先把首页加载速度做好。
3. 评论查询改成一次取全树，避免数据量上来后变慢。
4. 需要多作者时，把作者判断从 username 改成 user id。
5. 有真实流量后再考虑 PostgreSQL、缓存和全文搜索。

## 写在最后

个人博客最重要的是“能一直写”。功能可以慢慢加，但写作、阅读、评论这条主链路要稳定。先把这条链路跑顺，再谈推荐、搜索和社交。
