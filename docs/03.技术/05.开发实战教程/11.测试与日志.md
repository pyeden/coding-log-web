# 11. 测试与日志

## 这一章解决什么

让“改坏了”能尽早被发现，让线上问题有记录可查。

## 测试范围

后端 51 个测试，分四组：

- `accounts`：注册、登录、me、资料、头像、CSRF、密码重置、删除账号、Profile 信号。
- `blog`：slug、分页、搜索、栏目/标签过滤、CRUD 权限、点赞幂等、封面、Markdown 清洗、浏览量、最热。
- `comments`：两级树、父评论校验、通知、删除权限。
- `notices`：列表形状、未读数、单条/全部已读、越权 404。

运行：

```bash
cd backend
source .venv/bin/activate
python manage.py test
```

期望：

```text
Ran 51 tests in 14.7s
OK
```

## 测试怎么写

用 `APIClient` 走真实路由，不直接调视图函数：

```python
self.client.force_login(self.author)
response = self.client.post("/api/articles/", {"title": "Hello", "body": "..."}, format="json")
self.assertEqual(response.status_code, 201)
```

权限测试要覆盖三种身份：匿名、作者、非作者/staff。只测“作者能改”是不够的。

## 日志

`LOGGING` 同时输出 console 和 `logs/app.log`，按 5MB 轮转、保留 3 份：

```python
"file": {
    "class": "logging.handlers.RotatingFileHandler",
    "filename": str(LOG_DIR / "app.log"),
    "maxBytes": 5 * 1024 * 1024,
    "backupCount": 3,
}
```

生产把 `DJANGO_LOG_LEVEL` 设为 INFO；排查问题时临时降到 DEBUG，不要长期开。

## 冒烟脚本

`qa/smoke_api.sh` 覆盖 17 项：列表、热门、栏目、标签、CSRF、登录、详情、评论、创建、修改、点赞×2、评论、删除、搜索、通知、me。本地和生产都能跑：

```bash
BASE=http://127.0.0.1:8000 ./qa/smoke_api.sh
BASE=https://seres-ai.com/djangovueblog ./qa/smoke_api.sh
```

脚本会创建并删除一篇 QA 文章，不污染数据；登录后要重新取 CSRF token。

## 验证

- 全量测试全绿。
- 日志文件出现请求记录。
- 冒烟脚本 17/17。

## 小结

测试保证“已知行为不退化”，日志保证“未知问题可回看”。下一章把项目放到线上。
